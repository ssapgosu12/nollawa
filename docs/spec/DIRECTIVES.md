# 사용자 지시 원문 (DIRECTIVES)

**이 파일은 가공하지 않는다.** 사용자가 친 말을 날짜와 주제만 붙여 그대로 보관한다.
계획 문서는 여기서 도출되며, 도출이 원문과 어긋나면 **원문이 이긴다.**

왜 원문을 따로 보관하는가 — 가공본만 남으면 몇 세대 뒤에 "사용자가 승인했다"는 문장이
모델이 쓴 문장을 순환 인용하게 된다(승인 세탁). 원문이 남아 있어야 대조가 가능하다.

읽는 법: 필요한 지시 하나만 찾아 읽는다. 각 항목의 제목 줄에 날짜와 주제가 있다.

## D-001 · 2026-08-12 · 메인 화면과 방 로비 구조

> 방 흐름에 대해서: 메인화면에 이 기기에서 플레이, 방 참여, 방 생성 이렇게 3개로 하고 이 기기에서를 누르면 바로 게임 목록으로, 방 참여 혹은 방 생성을 누르면 방 로비로 이어지게 하자. 방 로비에서는 상단에 화면높이의 20%정도 영역에 현재 게임이 나오고, 게임 제목과 함께 플레이 인원수, 태그(예: 파티, 협동 등) 나오도록 하고, 게임 카드영역 오른쪽에서 (...) 버튼을 두어서 누르면 게임 설정 변경(텍사스 홀덤을 예시로 들면 시작 크레드, 최대 배팅가능 크레드, 올인 여부 변경)할수 있게 하자. 아래쪽 60%에 2*3 격자로 현재 플레이어와 방 생성한사람에게 왕관표시(방장 표시) 띄우자. 사람들 옆에 현재 준비상태가 나오게 하자. 방 코드는 최상단에 큼지막하게 나오게 하자. 제일 하단에는 플레이 시작 버튼이 있고, 현재 준비상태인 플레이어 명수 나오게 하자. (현재 방이 4명인데 3명 준비인경우: '3/4 준비됨') 플레이 시작은 방장이 누를수 있고, 2명일경우에는 2명 다, 3명일경우에는 2명만 준비해도 되게, 4명과 5명일경우 3명 준비, 6명일경우 4명 준비여야지 시작할수 있게 하자. 게임 시작 버튼의 왼쪽에는 게임 변경 버튼을 두자. 방장이 아닐경우에는 게임 시작버튼이 비활성화되고, 게임 변경 버튼에서는 게임 목록만 볼수 있고 정작 선택은 안되게 하자. 방장의 경우에 각 유저 카드 옆에 (...) 메뉴를 두어서 누르면 팝업으로 추방, 방장으로 승격등의 메뉴를 띄우자.

## D-003 · 2026-08-12 · 팀 대전과 투표 (D-001의 정원 초과 처리를 정정)

앞서 "정원 초과면 시작 불가"로 답했던 것을 사용자가 직접 정정한 것이다. 그 답은 폐기한다.

> 아니다. 6명방에서 2인용 사목두는경우에 정정. 1팀 2팀을 나누고 (2*3명 있는 로비에서 왼쪽열와 오른쪽열로 구분. 팀명은 방장이 지정 가능, 기본값으로는 (콜라, 사이다), (짜장, 짬뽕), (부먹, 찍먹), (인도어, 아웃도어) 등등 재치있는 대립되는 문자열로 랜덤 지정하자. 두 팀에서 번갈아가며 두게 하고, 각 팀의 순서에는 투표 형식으로 하자. 모든 표가 한곳으로 모이거나, 최초 1표가 투표되고 15초 경과되거나, 과반이 투표하고 5초 지나면 그 선택지로 정해지게 하자. 사목의 경우에 각 라인의 아래에 점 모양 아이콘으로 몇명이 투표했는지 보이게 하자.

## D-007 · 2026-08-12 · 티켓은 만들면 발행한다

> 티켓 만들면, 발행해. 당연히 티켓은 발행하기위해 만든거고, supervisor가 길게 들고있어봤자 딱히 쓸모없어. 내가 발행해 라고 하면 발행해서 보내는거야. 그냥 기능 제안만 하면 이런식으로 멀티턴 지시를 통해 티켓에 내용을 쌓는거고.

**해석**: 사용자가 "발행해"라고 하면 supervisor는 카드를 만들어 **그 자리에서 `up`까지 한다.**
기능 제안만 오면 발행하지 않고 사양을 쌓아 둔다. 쪼갤 때 **작업 카드는 최대 3장**이다.
