# 사용자 지시 원문 (DIRECTIVES)

**이 파일은 가공하지 않는다.** 사용자가 친 말을 날짜와 주제만 붙여 그대로 보관한다.
계획 문서는 여기서 도출되며, 도출이 원문과 어긋나면 **원문이 이긴다.**

왜 원문을 따로 보관하는가 — 가공본만 남으면 몇 세대 뒤에 "사용자가 승인했다"는 문장이
모델이 쓴 문장을 순환 인용하게 된다(승인 세탁). 원문이 남아 있어야 대조가 가능하다.

읽는 법: 필요한 지시 하나만 찾아 읽는다. 각 항목의 제목 줄에 날짜와 주제가 있다.

## D-001 · 2026-08-12 · 메인 화면과 방 로비 구조

> 방 흐름에 대해서: 메인화면에 이 기기에서 플레이, 방 참여, 방 생성 이렇게 3개로 하고 이 기기에서를 누르면 바로 게임 목록으로, 방 참여 혹은 방 생성을 누르면 방 로비로 이어지게 하자. 방 로비에서는 상단에 화면높이의 20%정도 영역에 현재 게임이 나오고, 게임 제목과 함께 플레이 인원수, 태그(예: 파티, 협동 등) 나오도록 하고, 게임 카드영역 오른쪽에서 (...) 버튼을 두어서 누르면 게임 설정 변경(텍사스 홀덤을 예시로 들면 시작 크레드, 최대 배팅가능 크레드, 올인 여부 변경)할수 있게 하자. 아래쪽 60%에 2*3 격자로 현재 플레이어와 방 생성한사람에게 왕관표시(방장 표시) 띄우자. 사람들 옆에 현재 준비상태가 나오게 하자. 방 코드는 최상단에 큼지막하게 나오게 하자. 제일 하단에는 플레이 시작 버튼이 있고, 현재 준비상태인 플레이어 명수 나오게 하자. ## D-007 · 2026-08-12 · 티켓은 만들면 발행한다

> 티켓 만들면, 발행해. 당연히 티켓은 발행하기위해 만든거고, supervisor가 길게 들고있어봤자 딱히 쓸모없어. 내가 발행해 라고 하면 발행해서 보내는거야. 그냥 기능 제안만 하면 이런식으로 멀티턴 지시를 통해 티켓에 내용을 쌓는거고.

**해석**: 사용자가 "발행해"라고 하면 supervisor는 카드를 만들어 **그 자리에서 `up`까지 한다.**
기능 제안만 오면 발행하지 않고 사양을 쌓아 둔다. 쪼갤 때 **작업 카드는 최대 3장**이다.
