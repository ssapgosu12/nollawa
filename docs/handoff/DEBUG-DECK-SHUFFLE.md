# 덱 섞기 "반으로 갈라져 보임" — 가설 원장과 원점 재검토

2026-08-14. 같은 증상에 수정이 **2회 무효**가 되어 `two-strikes` 규율로 전환했다.
세 번째 변형 수정을 만들지 않고, 원인 귀속부터 다시 한다.

## 앵커 (실독)

- **목표**(D-015 원문): 「1개의 덱 나타남 → 덱이 반반 갈라짐 → 다시 합쳐짐 → 인터레이스 방식으로
  서서히 사라짐」. **한 덩어리의 섞기로 보이면 된다**(D-015-a).
- **불변조건**: 부르는 쪽이 시작시킬 때만 재생 · 인터레이스는 10px 단위 · 인터레이스는 **사라질 때만**
  쓰는 장치이고 카드 면의 상시 무늬가 아니다(D-020) · 자막 「OO덱이 섞이고 있습니다」 · 흑백만.
- **허용 변경 범위**: `src/components/Effects.tsx`의 `DeckShuffle`과 `src/styles.css`의 덱 구간.

## 최초 귀속의 재분류

가설 #2에서 "기울기·벌어짐"을 원인으로 고른 근거는 **사진 관찰**이었다(두 조각이 실제로 기울어
있었다). 그것은 사실이었다. 그러나 그때 **묻지 않은 것**이 있다 — 왜 애초에 두 조각인가.
`DeckShuffle`은 처음부터 `shuffle-half shuffle-left`와 `shuffle-half shuffle-right` **두 요소**로
덱을 만든다. 즉 **"한 장의 덱"이라는 것이 코드에 존재하지 않는다.** 합쳐진 상태조차 두 반쪽을
같은 자리에 겹쳐 흉내낸 것이다. 기울기를 없애고 간격을 줄인 것은 **두 조각이라는 사실을 덜 눈에
띄게 만든 것**이지 한 덩어리로 만든 것이 아니다. 사용자의 "아직도 반갈죽"은 그 잔여를 가리킨다.

## 인과 사슬 역추적 — 잘못된 상태가 처음 만들어지는 지점

1. `Effects.tsx` `DeckShuffle`: 덱을 `shuffle-left` + `shuffle-right` 두 조각으로 **생성**. ← 생성 지점
2. `styles.css` `.shuffle-left/right`: 각각 `clip-path`로 자기 절반만 보이게 자름. 두 조각은
   `.shuffle-piece`의 테두리(3px)와 내부 링(`inset 0 0 0 7px`, `9px`)을 **각자** 갖는다.
3. `@keyframes shuffle-halves`: 22·38·54%에서 각자 `--shuffle-split`(±0.18rem)만큼 벌어졌다 모인다.
4. 관측: 정지 구간(6~14%·30%·46%·62~66%)에도 중앙에 이음선이 보이고, 벌어지는 구간에는 그 사이로
   배경이 보인다 → **"반갈죽"**.

기각된 두 가설은 모두 3번 층(움직임의 크기)을 다뤘다. 생성 지점은 1번이다.

## 새 가설 (#3) 과 자격

- **가설**: 증상의 생성 지점은 움직임이 아니라 **구조**다 — 합쳐진 상태를 두 조각으로 흉내내기 때문에
  경계가 화면에 남는다. 갈라짐의 양을 0으로 만들어도 두 조각의 테두리·링·안티에일리어싱 경계는 남는다.
- **기각 가설과 다른 점**: #1·#2는 "얼마나 움직이는가"를, #3은 "무엇을 그리는가"를 지목한다.
- **#1·#2가 설명하지 못한 관찰**: 벌어짐을 3px까지 줄였는데도 중앙선이 남는다.

## 다음에 할 가장 싼 결정적 관찰 (구현 전)

**모션 줄이기 설정(`prefers-reduced-motion: reduce`)에서는 `.shuffle-piece`의 애니메이션이 꺼진다**
(`styles.css`의 reduced-motion 블록). 그 상태로 덱을 띄우면 **정지된 합쳐진 상태**를 볼 수 있다.
거기서 중앙 이음선이 보이면 가설 #3은 확정, 안 보이면 기각이고 원인은 움직임 구간에만 있다.
관찰 방법: 브라우저에서 모션 줄이기를 켜고 덱 섞기를 눌러 확대 캡처 1장. 도구가 한 대뿐이므로
검수 서브에이전트가 끝난 뒤에 수행한다.

## 수리 방향 (관찰이 #3을 확정하면)

한 장의 덱 요소를 실제로 두고, **갈라지는 구간에서만** 두 반쪽을 보이게 한다(합쳐진 구간에는 한 장만
존재). 그러면 정지·합쳐진 상태에 경계가 원리적으로 없다. 이것은 3번 층의 값 조정이 아니라 1번 층의
생성 구조 변경이며, `two-strikes`가 요구하는 "생성 지점 수리"에 해당한다.
