# 방 흐름과 방 로비

**무엇에 대한 문서인가**: 메인 화면 → 방 로비 → 게임 목록으로 이어지는 화면 흐름, 방 코드 규격,
방장 권한과 준비 규칙. 게임 규칙은 이 문서에 없다(게임별 문서를 본다).

**원문**: `docs/spec/DIRECTIVES.md` D-001. 아래 내용과 원문이 어긋나면 원문이 이긴다.
**전역 제약**: `docs/PLAN.md` §5 색 · §6 화면 규칙 · §11 구조 예산. 이 문서가 그것을 덮어쓰지 않는다.

각 항목은 **[원문]**(사용자가 지정) 또는 **[도출]**(그 지시에서 계획이 끌어낸 것)로 표시한다.
[도출]은 사용자 승인 없이 뒤집을 수 있고, [원문]은 뒤집을 수 없다.

---

## 1. 화면 흐름

```
[이름]  최초 1회만. 기기에 저장되고 서버에 남지 않는다. 언제든 바꾼다.
   │
[메인]  ┌ 이 기기에서 플레이 ──────────────→ [게임 목록]   (방 로비를 건너뛴다)
        ├ 방 참여  [ABC-67] ───┐
        └ 방 생성 ─────────────┴─────────→ [방 로비]
                                              │
                                       게임 변경 ↕ (방장만 선택 가능)
                                              │
                                          [게임 목록]
                                              │
                                    플레이 시작(방장) → [대국]
```

- [원문] 메인 화면의 버튼은 **이 기기에서 플레이 · 방 참여 · 방 생성** 셋이다.
- [원문] **이 기기에서 플레이를 누르면 곧장 게임 목록**으로 간다. 방 로비를 거치지 않는다.
- [원문] **방 참여와 방 생성은 방 로비**로 간다.
- [도출] 이름 입력은 최초 1회로 남는다(기존 §4). 두 번째 실행부터 메인 화면이 첫 화면이다.
- [도출] 화면 흐름에서 로비를 건너뛰는 것이지 **코드 경로가 갈라지는 것이 아니다.** 통신 계층
  (`Transport`)에 자기 자신에게 되돌려 주는 구현을 두어 로컬·원격이 같은 경로를 타는 기존 설계를
  유지한다. 로비 코드가 두 벌로 갈라지는 것을 막기 위한 것이고, 이 원칙은 바뀌지 않았다.

## 2. 방 로비 화면

세로 배분은 `100svh` 기준이다(`dvh` 금지 — `PLAN.md` §6).

```
┌──────────────────────────────────┐
│           ABC-67                 │  최상단 · 방 코드 · 큼지막하게
├──────────────────────────────────┤
│  텍사스 홀덤            2~6명    │  약 20% · 현재 게임 카드
│  #파티  #베팅  #숨긴정보   (…)   │  (…) = 게임 설정 변경
├──────────────────────────────────┤
│  ┌────────┐  ┌────────┐          │  약 60% · 2×3 격자 (최대 6인)
│  │👑 나    │  │  민수   │        │  왕관 = 방장
│  │  준비   │  │  준비   │  (…)   │  (…) = 방장에게만 보이는 유저 메뉴
│  ├────────┤  ├────────┤          │
│  │  지원   │  │ (빈자리)│        │
│  │  대기   │  │         │        │
│  ├────────┤  ├────────┤          │
│  │(빈자리) │  │(빈자리) │        │
│  └────────┘  └────────┘          │
├──────────────────────────────────┤
│  [게임 변경]   [플레이 시작]     │  최하단
│              3/4 준비됨          │
└──────────────────────────────────┘
```

- [원문] **방 코드는 최상단에 큼지막하게.**
- [원문] AI 대전이 켜져 있으면 **게임 이름 옆에 `(AI 대전)`을 붙인다**(2026-08-13 D-014) —
  `사목 (AI 대전)`. 팀명 자리가 바뀌는 것 말고는 게임 카드만 봐서는 AI 대전인지 알 수 없었다.
- [원문] **상단 약 20%에 현재 게임** — 게임 제목, 플레이 인원수, 태그(파티·협동 등).
- [원문] 게임 카드 **오른쪽에 `(…)` 버튼** — 누르면 **게임 설정 변경**. 텍사스 홀덤 예: 시작 크레딧,
  최대 베팅 가능 크레딧, 올인 허용 여부.
- [원문] **아래쪽 약 60%에 2×3 격자**로 현재 플레이어. **방을 만든 사람에게 왕관 표시**(방장).
- [원문] **사람들 옆에 현재 준비 상태**가 나온다.
- [원문] 상태는 **다섯 가지**다(2026-08-13 D-011) — `대기` · `준비` · **`게임 목록 보는 중`** ·
  **`게임 중`** · `연결 끊김`.
- [도출] 상태는 그 사람이 **지금 어느 화면에 있는지**다. 화면을 옮기면 방 명령으로 알리고 릴레이가
  방 상태에 실어 방송한다 — 화면 위치는 방 규칙이므로 릴레이 소관이라는 경계와 맞는다.
- [도출] 이 표시가 **유령 멤버를 눈으로 가른다.** 대국이 도는 중에 새로 들어온 사람은 `대기`,
  두고 있는 사람은 `게임 중`으로 갈려 보인다. `연결 끊김`은 다른 넷과 겹칠 수 있으며 그때는
  `연결 끊김`을 우선해 보인다.
- [원문] **최하단에 플레이 시작 버튼**, 그 **왼쪽에 게임 변경 버튼**, 그리고 **준비된 인원수**
  (예: 방에 4명이고 3명이 준비했으면 `3/4 준비됨`).
- [도출] 2×3은 **화면 폭과 무관하게 2열 3행**이다. 처음에는 가로가 넓은 태블릿에서 3열 2행으로
  눕히기로 했으나 **폐기했다**(2026-08-13, PC 실기기 검수) — §8.1 [원문]이 왼쪽 열을 1팀,
  오른쪽 열을 2팀으로 못박으므로 열이 셋이 되면 한 열에 두 팀이 섞이고 팀명 헤딩(2열)과도
  어긋난다. [원문]이 [도출]을 이긴다. 칸 수 6은
  한 방 최대 인원 6인과 같다(`PLAN.md` §0 규모 전제).
- [도출] **참가자 카드는 화면이 넓어져도 세로로 늘어나지 않는다**(D-008). PC에서 카드 하나가
  화면 높이의 3분의 1까지 자라 이름과 상태가 허공에 뜨는 것이 관측됐다. 격자는 위쪽으로 정렬하고
  칸 높이에 상한을 두어, 폰에서 보이는 비례를 넓은 화면에서도 유지한다.
- [도출] **`(…)` 유저 메뉴는 카드 오른쪽 위 모서리에 겹쳐 두지 않는다**(D-008). 카드 안에서
  이름·상태와 같은 흐름에 놓아 어디를 눌러야 하는지가 위치로 드러나게 한다.
- [도출] **방장이 아닌 사람에게는 「플레이 시작」 자리에 「준비」 버튼이 온다**(D-008). 참가자 카드
  안에 있던 준비 버튼은 없앤다 — 자기가 누를 것이 화면 두 곳에 흩어지지 않는다. 방장은 그 자리에
  「플레이 시작」을 갖고, 방장의 준비 여부는 OPEN-1이 정한다.
- [도출] 나머지 약 20%는 최상단 방 코드 줄과 최하단 버튼 줄이 나눠 갖는다. 20/60은 **고정 비율이
  아니라 목표 비율**이다 — 작은 폰에서 버튼이 잘리면 안 되므로 격자가 먼저 줄어든다(`PLAN.md` §6
  화면 잘림 금지가 상위 규칙).

## 3. 권한 — 방장과 그 외

| 기능 | 방장 | 그 외 |
|---|---|---|
| 플레이 시작 | 누를 수 있다 | **비활성** |
| 게임 변경 | 목록을 보고 **고를 수 있다** | 목록을 **볼 수만** 있고 고르지 못한다 |
| 게임 설정 변경 `(…)` | [도출] 할 수 있다 | [도출] 값만 보인다 |
| 유저 카드 `(…)` 메뉴 | 보인다 — **추방 · 방장으로 승격** 등 | 보이지 않는다 |
| 준비 상태 토글 | ↓ OPEN-1 | 누를 수 있다 |

- [원문] 방장이 아니면 **플레이 시작 버튼이 비활성화**된다.
- [원문] 방장이 아니면 게임 변경에서 **목록만 볼 수 있고 선택은 안 된다.**
- [원문] 방장에게만 각 유저 카드 옆 `(…)` 메뉴가 있고, 누르면 **팝업으로 추방·방장 승격** 등이 뜬다.
- [원문] 같은 팝업에 **그 사람을 n번 슬롯으로 옮기는** 기능도 넣는다. **빈 슬롯이면 바로 이동하고,
  목적지에 다른 사람이 있으면 둘이 자리를 맞바꾼다.** (팀 조정용 — 왼쪽/오른쪽 열이 곧 팀이므로
  이 기능이 팀을 짜는 수단이다)
- [도출] 자리 이동은 **준비 상태를 푼다.** 팀이 바뀌었는데 준비가 남아 있으면 다른 팀에 동의한 것이
  되어 버린다. 맞바꾼 두 사람 모두 풀린다.
- [도출] 대국 중에는 자리를 옮길 수 없다. 로비에 있을 때만 가능하다.
- [도출] 게임 설정 변경도 방장 권한으로 둔다 — 게임 선택이 방장 권한인데 그 게임의 규칙 옵션만
  누구나 바꿀 수 있으면 앞의 제한이 무의미해진다.

## 4. 시작 조건 — 준비 인원

[원문] 방 인원별로 필요한 준비 인원:

| 방 인원 | 시작에 필요한 준비 인원 |
|---|---|
| 2명 | **2명** |
| 3명 | **2명** |
| 4명 | **3명** |
| 5명 | **3명** |
| 6명 | **4명** |

- [도출] 이 표는 **⌊n/2⌋+1**(과반)과 정확히 일치한다. 구현은 표를 하드코딩해도 되고 식을 써도
  되지만, **표가 정본이다** — 나중에 사용자가 한 칸만 바꾸면 식은 깨진다.
- [도출] 조건을 못 채우면 플레이 시작 버튼은 비활성이고, 방장이 눌러도 시작되지 않는다.
- [도출] `3/4 준비됨`의 분모는 필요 준비 인원이 아니라 **누를 수 있는 사람의 수**다. OPEN-1이
  ⓑ로 정해졌으므로 방장은 분모에서 빠진다 — 4명 방이면 `/3`이다(원문 예시의 `/4`는 방장도 누른다는
  전제였고, 그 전제가 2026-08-13에 바뀌었다).

## 5. 방 코드 규격 (기존 §4에서 이관 · 확정)

**`ABC-67` — 영문 3자 + 하이픈 + 숫자 2자.**

- 영문은 **대소문자 구분 없음**(입력 즉시 대문자로 정규화). **`I` · `L` · `O`를 뺀 23자**만 쓴다 —
  각각 `1` · `1` · `0`과 혼동되기 때문이다.
- 숫자는 0~9 전부. **글자 자리와 숫자 자리가 위치로 분리돼 있어** `0`/`O` 혼동이 생기지 않는다.
- 총 경우의 수 **23³ × 10² = 1,216,700개.**

| 확인 항목 | 결과 |
|---|---|
| 동시 방 20개일 때 코드 충돌 확률 | 0.0164% |
| 동시 방 100개일 때 | 0.4109% |
| 무작위 추측이 활성 방에 걸릴 확률(동시 20개) | 0.00164% |
| 10% 확률로 남의 방을 맞히는 데 필요한 시도 | 약 6,400회 |

월 이용자 30~300명 규모에서 충돌·추측 모두 실질 문제가 아니다. 다만 둘은 반드시 넣는다:

1. **생성 시 중복 검사.** 릴레이가 방 코드를 그대로 Durable Object 이름으로 쓰므로(`idFromName`),
   같은 코드가 두 번 나오면 **서로 모르는 두 무리가 같은 방에 들어간다.** (M0-FIX에서 구현 완료)
2. **금칙 조합 차단.** 3글자 조합 12,167개에는 불쾌한 것이 섞인다. 단톡방에 붙여 넣는 코드이므로
   수십 개짜리 블록리스트를 둔다. **상표 금칙어 게이트와 같은 파일에 두지 않는다** — 목적이 다르다.

**입력 UI**: 한 칸짜리 텍스트 입력에 `autocapitalize="characters"`, 3자 입력 시 하이픈 자동 삽입,
허용 문자가 아닌 입력은 무시. **숫자 자판을 강제로 띄우지 않는다**(앞 3자가 문자라 전환이 번거롭다).
공유 주소는 `#/r/ABC-67` 형태로 하이픈을 그대로 쓴다.

## 6. 게임 목록 (기존 §4에서 이관)

- **인원 구분 3개**: 1인 / 2인 / 3~4인. 방 인원이 정해져 있으면 **안 되는 게임은 흐리게 표시하되
  숨기지 않는다**(뭐가 있는지는 보여야 한다).
- **태그(다중 선택 시 좁혀짐)**: 봇 있음 · 대전 · 협동 · 동시진행 · 점수판 · 실물 필요 · 5분 이내 ·
  숨긴 정보.
- **검색**: 이름 + 별칭. 단 별칭 목록을 상표 grep 게이트의 예외로 두지 않는다 — 검색어는 사용자
  입력이지 우리 문자열이 아니므로, 코드에 상표를 넣지 않고 초성·유사어 매칭으로 처리한다.
- 게임 카드에는 **인원·소요 시간·태그**만 표시한다. 설명은 들어가서 본다.

## 7. 방이 게임보다 먼저 존재한다 (설계 근거 · 유지)

한 방에서 게임을 갈아 끼울 수 있다. 오목 한 판 두고 나가지 않고 바로 요트로 넘어간다. 매 판 방을
다시 만드는 기존 서비스 대비 실질 차별점이고, 리듀서 레지스트리 설계와도 맞는다. **게임 변경 버튼이
로비 최하단에 상시 있는 이유가 이것이다.**

## 8. 팀과 투표 — 정원보다 사람이 많을 때 (D-003)

**앞서 "정원 초과면 시작 불가"로 잡았던 OPEN-4는 폐기됐다.** 사용자가 직접 정정했고, 6명이 2인용
게임을 함께 하는 방식으로 대체됐다.

### 8.1 팀 나누기

- [원문] 2인용 게임은 **1팀 / 2팀**으로 나눈다. 로비의 2×3 격자에서 **왼쪽 열이 1팀, 오른쪽 열이 2팀**이다.
- [원문] **팀명은 방장이 지정할 수 있다.** 기본값은 재치 있게 대립되는 문자열 쌍을 무작위로 고른다.
- [원문] 기본 쌍 예시: **콜라/사이다 · 짜장/짬뽕 · 부먹/찍먹 · 인도어/아웃도어**
- [도출] 같은 결의 추가 후보: 민초/반민초 · 물냉/비냉 · 산/바다 · 고양이/강아지 · 여름/겨울 ·
  아침형/저녁형 · 단팥/슈크림. 목록은 한 곳에 두고 방을 만들 때 한 쌍을 뽑는다.
- [도출] 자리를 옮겨 팀을 바꾼다 — 빈 칸을 누르면 그 자리로 간다. 방장은 유저 카드의 `(…)` 메뉴로
  다른 사람을 옮길 수 있다(추방·방장 승격과 같은 자리).
- [도출] **인원이 같지 않아도 된다.** 3대1도 가능하다 — 친구들끼리 노는 판이지 공식전이 아니다.
  다만 **각 팀에 최소 한 명**은 있어야 시작한다.
- [원문] 두 팀이 **번갈아** 둔다. 즉 게임의 1번·2번 좌석이 사람이 아니라 **팀**에 배정된다.

### 8.2 한 수를 정하는 투표

자기 팀 차례가 오면 그 팀 사람들이 **어디에 둘지 투표**한다. [원문]

**확정 조건 — 둘 중 먼저 성립하는 것** [원문 · 2026-08-13 D-012로 개정]

| | 조건 | 확정되는 것 |
|---|---|---|
| A | **팀 전원**이 같은 곳에 투표 | 그 선택지 |
| B | **마지막 투표로부터 n초** 경과 | 그 시점 최다 득표 |

**n = (아직 투표하지 않은 사람 수) × 4 + 7초.** 아직 투표하지 않은 사람이 **0명이면 n은 1초로
고정**하고, 그때는 §8.4의 비네트와 카운트다운을 **띄우지 않는다**(1초는 알릴 만큼 길지 않다).

- [원문] 예전 조건 ②(최초 1표로부터 15초)와 ③(과반 투표 후 5초)은 **폐기됐다.** 표를 바꾸면
  타이머가 다시 시작하지만 그때는 미투표자가 0이라 1초만 더 가면 끝나므로 상한이 자연히 생긴다.
- [도출] **혼자인 팀은 A로 즉시 확정된다** — 1표가 곧 전원이므로 지금과 똑같이 바로 둔다.
  기다림이 생기는 것은 2명 이상인 팀뿐이다.
- [도출] **최초 1표가 없으면 타이머는 시작하지 않는다**(OPEN-8 무한 대기 유지). 마지막 투표가
  있어야 그로부터 셀 수 있다.
- [원문] **동점이면 무작위로 뽑되 룰렛처럼 보여 준다.** 하이라이트가 **최대 세 선택지**를 점멸하며
  순환하고, **선택지 사이 체류 시간이 점점 늘어나다가** 한 곳에서 멈춘다.
- [도출] 무작위 결과는 **대표 클라이언트가 정해 판 상태에 실어 보낸다.** 연출은 각자 자기 화면에서
  재생하지만 멈추는 자리는 모두 같다 — 각자 굴리면 서로 다른 곳에 멈춘다.
- [도출] 동점 후보가 넷 이상이면 **당첨을 포함해 셋만** 룰렛에 올린다(원문의 "최대 세 선택지").
- [도출] **돌은 연출이 완전히 끝난 뒤에 놓인다**(2026-08-13 D-009). 확정 시점에는 어디로 정해졌는지만
  판 상태에 실리고, 룰렛이 멈춘 다음 대표 클라이언트가 그 수를 적용한다. 돌이 먼저 놓이고 그 위에서
  룰렛이 도는 것은 결과를 미리 알려 주는 것이라 연출의 의미가 없다.
- [도출] 연출 길이는 약 2초, 순환 6~8회. 체류 시간은 처음 100ms에서 마지막 400ms로 늘린다.
  **연출은 결과를 바꾸지 않는다** — 이미 정해진 답을 보여 주는 것뿐이므로, 도중에 창을 닫거나
  화면이 멈춰도 확정된 수는 그대로다.
- [도출] 확정 전까지 **표를 바꿀 수 있다.** 바꾸면 A 조건을 다시 따진다.
- [도출] 타이머는 **대표 클라이언트(authority)가 잰다.** 릴레이는 투표 내용을 보지 않는다 —
  릴레이에 게임 규칙을 올리지 않는다는 §11 경계를 그대로 지킨다. 대표가 바뀌어도 투표 상태는
  판 상태에 실려 전달되므로 이어진다.

### 8.3 화면 — 몇 명이 어디에 걸었는지 보인다

- [원문] 사목은 **각 열 아래에 점 아이콘**으로 그 열에 투표한 인원수를 보인다.
- [도출] 자기가 투표한 열의 점 하나는 **자기 좌석 색**으로 칠해 자기 표를 알아보게 한다.
- [도출] 상대 팀 차례에도 점은 보인다 — 숨길 이유가 없고, 파티게임의 재미는 서로 훈수하는 데 있다.

### 8.4 남은 시간을 알린다 (D-012)

- [원문] **5초 남았을 때부터** 화면 가장자리만 **아주 가볍게 검정 그래디언트**로 점멸시킨다
  (비네팅). 주기는 **1초에 한 번**이고 **3초부터는 250ms**로 줄인다.
- [원문] **남은 초를 숫자로 화면 제일 하단에** 띄운다.
- [원문] 미투표자가 0명이라 n이 1초로 고정된 경우에는 **둘 다 끈다.**
- [도출] 비네트와 카운트다운은 이 투표 전용이 아니라 **다른 게임도 부를 수 있는 공용 도구**다.
  사양과 구현은 `table-effects.md` §6·§7이 정본이고 투표는 그것을 불러 쓴다 — 동전·주사위·룰렛과
  같은 자리에 놓인다.

## 9. AI 대전 — 사람 전원이 한편 (D-008)

- [원문] **방장이 게임 설정에서 AI 대전을 켜면, 팀 1·팀 2 상관없이 사람들이 같이 AI와 대전한다.**
- [원문] 선택지(한 수 투표)는 §8.2 규칙을 **그대로** 쓴다 — 전원일치·첫표 15초·과반 5초.
- [원문] **AI 대전을 켜면 6명 전원이 한 팀이다**(2026-08-13 D-013). 3명이 AI 편, 3명이 사람 편으로
  갈리는 것이 아니다.
- [도출] 좌석은 **사람 전원이 1번, AI가 2번**이다. 왼쪽/오른쪽 열이 팀을 가르는 규칙은 이 모드에서
  쉰다.
- [도출] **격자 6칸은 전부 사람 자리다.** AI는 격자에 칸을 차지하지 않는다 — 자리를 차지하면 사람이
  앉을 곳이 줄고 오른쪽 열이 AI 편처럼 보인다(3회차 검수에서 실제로 그렇게 보였다).
- [도출] 팀명 두 개를 보이던 자리에는 **AI와 겨루는 중임을 한 줄로** 알린다. 「사람 편 / AI」처럼
  좌우로 갈라 쓰지 않는다 — 그 표기 자체가 격자를 둘로 나눠 보이게 만든다.
- [도출] 시작 조건에서 **"각 팀에 최소 한 명" 검사는 적용하지 않는다**(2번 좌석이 AI이므로).
  준비 인원 표(§4)는 사람 수 기준으로 그대로 쓴다.
- [도출] **AI는 약 1초 뒤에 둔다**(2026-08-13 D-009). 즉시 두면 사람이 자기 수의 결과를 보기 전에
  판이 바뀌어 따라가기 어렵다. 이 지연은 연출이지 사고 시간이 아니므로 AI 강도와 무관하다.
- [도출] 사람이 혼자면 지금의 「AI와 시작」과 같은 판이 된다 — 별도 경로를 만들지 않고 같은 코드가
  인원 1명인 경우로 처리한다.
- [도출] AI 대전 여부는 방 상태에 실려 모두에게 같은 값으로 보인다. 방장만 켜고 끌 수 있다(§3의
  게임 설정 변경 권한과 같다).
- [원문] **AI 강도를 보통과 높음 중에서 고른다**(2026-08-13 D-011). 강도별 시간 예산과 대기시간은
  `PLAN.md` §6.5-a가 정본이다. 기본값은 보통이고 방장만 바꾼다.
- [도출] **AI 대전 토글이 놓이는 자리를 이번에 만든다**(2026-08-13 사용자 결정). §2가 정한 게임 카드
  오른쪽 `(…)` 버튼을 눌러 열리는 **게임 설정 팝업**이 그것이고, 지금은 그 안에 AI 대전 하나만
  들어간다. 나중에 홀덤의 시작 크레딧 같은 설정이 여기에 늘어난다. 방장이 아니면 값만 보인다(§3).

## 10. 대국에서 나가기 (D-009)

- [원문] 대국 화면에 **로비로 돌아가기**와 **타이틀로 나가기**가 있어야 한다.
- [원문] **일반 참가자가 로비로 돌아가면 게임에서도 나가진다** — 유령 멤버가 판에 남는 것을 막기 위해서다.
- [원문] **방장이 로비로 돌아가면 모든 멤버가 함께 로비로 나간다.**
- [원문] **로비로 돌아가면 준비 상태는 자동으로 취소된다.**
- [원문] **방 단계는 "판이 끝났는가"가 아니라 "나갔는가"로 통제한다**(2026-08-13 D-010 확정).
  판이 끝나도 「다음 판」으로 이어가면 **계속 대국 상태**이고, 「로비로 돌아가기」를 눌렀을 때만
  방이 로비로 돌아간다. 판의 끝과 방의 단계는 별개다 — 판이 끝날 때마다 로비로 돌리면 이어하기와
  충돌한다.
- [도출] 방 단계를 되돌리는 것은 **릴레이가 한다.** 지금은 되돌리는 경로가 아예 없어 판을 한 번
  시작하면 방이 영영 대국 중이고, 그래서 준비 명령과 자리 이동이 거부된다(`PLAN.md` §14 2회차
  P3·P6). 방 단계는 방 규칙이므로 릴레이 소관이라는 기존 경계와 일치한다.
- [도출] 방장의 「로비로 돌아가기」는 **방 단계를 되돌리고 전원의 준비를 푸는 방 명령**이고, 참가자의
  「로비로 돌아가기」는 **자기만 방에서 나가는 것**이다. 이름이 같지만 방장 것은 방 전체에, 참가자 것은
  자기에게 작용한다 — 화면에도 그렇게 읽히도록 쓴다.
- [도출] **타이틀로 나가기**는 방에서 나가고 연결을 끊은 뒤 메인 화면으로 간다. 방장이 나가면 방장
  승계(OPEN-2)를 따른다.
- [도출] 판이 진행 중일 때 사람이 빠져 남은 인원으로 판이 성립하지 않으면 그 판은 끝내고 로비로
  돌린다. 억지로 이어 두면 아무도 둘 수 없는 판이 남는다.

## OPEN — 아직 정해지지 않은 것

착수 전에 사용자에게 물어야 한다. 임의로 정하고 구현하지 않는다.

- **OPEN-1 해소됨 (2026-08-13)** → **ⓑ 방장은 시작 버튼이 곧 준비다.** 방장은 하단에서 「플레이
  시작」 자리를 차지하므로 준비를 누를 자리가 없다(§2 D-008 도출). §4의 필요 준비 인원 표는 **방
  인원 기준 그대로 두고 방장을 늘 준비된 것으로 센다.** 표시되는 분모에서만 방장이 빠진다 —
  4명 방이면 방장 외 3명 중 2명이 준비했을 때 `2/3 준비됨`이고, 표가 요구하는 3명(방장 1 + 2)이
  채워져 시작할 수 있다.
- **OPEN-2 방장이 나가면 누가 방장이 되는가?** 남은 사람 중 가장 먼저 들어온 사람으로 자동 승계가
  기본값 후보. 아무도 없으면 방은 사라진다.
- **OPEN-3 게임을 바꾸면 준비 상태가 초기화되는가?** 다른 게임에 동의한 것이 아니므로 초기화가
  상식적이지만, 매번 다시 누르는 번거로움이 있다.
- **OPEN-4 해소됨 (2026-08-12 D-003)** → §8 팀과 투표. 정원 초과면 팀으로 나누고 한 수를 투표로 정한다.
- **OPEN-8 아무도 투표하지 않으면?** 최초 1표가 없으면 15초 타이머가 시작되지 않는다. 기본값은
  **무한 대기**로 둔다 — 파티게임이라 사람들이 떠드느라 늦는 것이 정상이고, 재촉이 오히려 방해다.
  실제로 답답하다는 말이 나오면 그때 넣는다.
- **OPEN-5 빈 칸의 모습.** 6칸 중 비어 있는 칸을 "빈 자리"로 둘지, 방 코드를 복사하는 초대 버튼으로
  쓸지.
- **OPEN-6 "이 기기에서 플레이"의 게임 설정 변경은 어디서 하는가?** 로비를 건너뛰므로 `(…)` 버튼이
  놓일 자리가 없다. 게임 목록의 카드에 두거나, 게임 시작 직전 화면에 두어야 한다.
- **OPEN-7 해소됨 (2026-08-13 D-008)** → 판이 끝나면 대국 화면에 남고, **방에 있는 플레이어
  전원이 「다음 판」을 눌러야 새 판이 열린다.** 한 명만 눌러도 즉시 시작하던 F1의 해법은 폐기됐다
  (`PLAN.md` §14 F1 정정). 전원 동의가 요구사항이 된 이상 **누가 눌렀고 누가 안 눌렀는지 보이는
  화면이 필요하다** — 대국 화면에 `2/4 준비됨` 꼴로 표시하고, 아직 안 누른 사람이 누구인지 알 수
  있게 한다. 기각됐던 대기 화면의 문제의식은 더 이상 기각 사유가 아니다.
