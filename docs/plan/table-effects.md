# 판 위 연출 — 동전 · 주사위 · 덱

**무엇에 대한 문서인가**: 게임 진행을 돕는 연출 세 가지(동전 던지기, 주사위 굴리기, 덱 섞기)의
사양. 게임 규칙은 이 문서에 없다.

**원문**: `docs/spec/DIRECTIVES.md` D-010. 아래 내용과 원문이 어긋나면 원문이 이긴다.
**전역 제약**: `docs/PLAN.md` §5 색 · §6 화면 규칙 · §11 구조 예산.

각 항목은 **[원문]**(사용자가 지정) 또는 **[도출]**(그 지시에서 계획이 끌어낸 것)로 표시한다.

---

## 1. 공통

- [원문] **게임 목록에 연출 테스트 페이지를 둔다.** 지금은 이 연출을 쓰는 게임이 없으므로 여기서
  확인한다.
- [원문] 동전과 주사위는 **「던지기!」 버튼으로 던지는 것과 자동으로 던져지는 것 두 가지**를 만든다.
- [원문] 시점은 **탑뷰**다. 화면 가운데에서 **화면을 뚫고 나오는 방향으로** 던져져 바닥에 떨어진다.
- [원문] 동전과 주사위는 **한 번쯤 가볍게 땅에 튕긴다.**
- [원문] **3D나 유사 3D가 힘들면 대체안을 써도 된다** — 동전은 림버스식(빙글빙글 돌다가 «핑!» 하며
  멈춤), 주사위는 마리오파티식(눈이 상자 열리듯 스크롤되다가 «틱!» 하고 한 번에 멈춤).
- [도출] 대체안을 골랐으면 **무엇을 왜 골랐는지 `REVIEW:`에 남긴다.** 두 방식을 모두 만들지 않는다 —
  하나만 고르고, 나중에 바꾸고 싶으면 그때 바꾼다.
- [원문·D-015] **결과는 무작위여야 한다.** 교차(H·T·H·T)나 순회(1·2·3…) 같은 고정 패턴을 쓰지 않는다.
  무작위를 만드는 것은 **부르는 쪽**이고(테스트 페이지가 그 예다) 연출 부품은 받은 값을 재생만 한다.
- [도출] **연출은 결과를 만들지 않는다.** 무엇이 나왔는지는 부르는 쪽이 정해서 넘기고 연출은 그것을
  재생할 뿐이다. 원격 대국에서 쓸 때는 대표 클라이언트가 결과를 정해 실어 보내고 각자 자기 화면에서
  재생한다 — `room-lobby.md` §8.2 룰렛과 같은 구조이며, 각자 굴리면 서로 다른 것을 본다.
- [도출] 흑백만 쓴다. 플레이어 구분 색(§5)은 이 연출에 들어가지 않는다.

## 2. 동전 던지기

- [원문·D-015] **현행 유지.** 2D 대체안(빙글빙글 돌다 멈춤)이므로 튕기지 않는 것이 맞고, 연출만으로도
  충분히 무작위로 보인다. 바꿀 것은 실제 값뿐이다.

- [원문] **최대 12개**를 동시에 던질 수 있다.
- [원문] 앞면은 **흰 바탕에 검은 글자 `H`**, 뒷면은 **검은 바탕에 흰 글자 `T`**.
- [도출] 개수는 테스트 페이지에서 고른다. 1개일 때와 12개일 때 모두 화면 안에 들어와야 한다(§6 화면
  잘림 금지가 상위 규칙).

## 3. 주사위 굴리기

- [원문·D-020] **튕기는 동안 눈은 두세 번만 바뀐다.** 지금은 너무 빠르고 많이 바뀌어 깜빡임으로 보인다.
- [원문·D-015] **한 번쯤 튕긴 다음에 눈이 보인다.** 위에서 떨어지는 굴림 모션인데 결과가 처음부터
  보이면 굴릴 때의 기대감이 사라진다. 떨어지는 동안과 튕기는 동안에는 결과를 알 수 없어야 하고,
  눈이 뒤죽박죽 바뀌다가 멈추는 것처럼 보여야 한다.

- [원문] **6면체만** 우선 만든다. **흰 주사위에 검은 눈.**
- [원문] **최대 6개**를 동시에 굴릴 수 있다.
- [원문] 3D로 만들면 **주사위끼리 어느 정도 부딪힌다.**
- [도출] 대체안(마리오파티식)을 골랐으면 부딪힘은 해당 사항이 없다.

## 4. 덱 섞기 (2026-08-14 D-025로 전면 교체)

- [원문] **덱은 하나만** 있으면 된다. 반투명 회색 레이어를 **화면 전체에** 깐다 → 덱을 스폰한다 →
  섞는다 → 인터레이스로 좌우로 갈라져 사라진다 → 레이어를 끈다.
- [원문] 자막 **「OO덱이 섞이고 있습니다」**를 함께 띄운다. 덱 이름은 부르는 쪽이 넘긴다.
- [원문·D-025] **자막 위치**: 화면 최하단이 아니라 **덱 바로 아래, 카드 너비의 20%만큼 띄운 자리**.
- [원문·D-025] **모든 시간(ms)은 슬라이더로 조정 가능**하게 만든다. 곡선은 아래 지정된 것으로 고정한다.
- [원문·D-015] 부르는 쪽이 시작시킬 때만 재생한다(페이지를 여는 것만으로 재생 금지).
- [원문·D-020] 인터레이스는 **사라질 때만** 쓰는 장치이고 카드 면의 상시 무늬가 아니다. 흑백만 쓴다.

### 4.1 스폰 — 카드 8장이 계단식으로 쌓인다

| 항목 | 값 | 출처 |
|---|---|---|
| 카드 수 | **8장** | 원문 |
| 낙하 방향 | 위에서 아래로 떨어지되, **뒤 카드가 앞 카드보다 화면 상단**에 놓여 계단식으로 쌓인다(내 쪽에서 멀어지는 방향) | 원문 |
| 1장당 낙하 시간 | **300ms** | 원문 |
| 카드 간 시작 간격 | **70ms** (첫 카드의 남은 시간이 230ms일 때 두 번째가 스폰) | 원문 |
| 페이드인 | 낙하 시작 후 **첫 150ms**에 완료 | 원문 |
| 낙하 곡선 | 초기속도 + 초당 가속으로 **자유낙하처럼**. 목적지 근처에서 **유압 댐퍼 같은 기계적 감속**. 또는 **초기속도가 있는 spring** | 원문 |
| 스폰 총길이 | 70×7 + 300 = **790ms** | 도출 |
| 스폰 후 대기 | **300ms** | 원문 |
| ~~모이기~~ | **2026-08-14 D-026으로 폐기** — 모으지 않고 쌓인 상태에서 곧바로 홀짝 두 뭉치로 섞는다 | D-026 |

### 4.2 섞기 — 2장으로 바꿔 좌우로 번갈아 지나간다

- [원문·D-026] **모이기 없이** 쌓인 8장을 **홀수번째 뭉치와 짝수번째 뭉치**로 나누어 그 두 뭉치로 섞는다.
  (D-025의 「8장을 2장으로 교체」는 이것으로 대체됐다.) 각 뭉치는 4장이고 이동·기울임 값과 시간표는 그대로다.
- [원문·D-026] **섞기 구간이 실제로 재생돼야 한다** — 현재 구현은 분리·합치기를 건너뛰고 곧바로 소멸로 넘어간다(결함).
- [원문] **덱 분리** = 한 장은 왼쪽, 한 장은 오른쪽으로 **카드 너비의 30%**씩 이동 + 왼쪽 카드는
  **반시계 20°**, 오른쪽 카드는 **시계 20°** 기울임. **이동과 기울임은 동시에** 일어난다.
  **덱 합치기** = 그 역.
- [원문·D-030] **분리할 때 각 뭉치가 가는 쪽이 사이클마다 뒤바뀐다.** 1번째에 홀(1·3·5·7)이 왼쪽·짝(2·4·6·8)이
  오른쪽이면 2번째는 홀이 오른쪽·짝이 왼쪽, 3번째는 다시 홀 왼쪽·짝 오른쪽이다. 기울임도 가는 쪽을 따른다
  (왼쪽 = 반시계 20°, 오른쪽 = 시계 20°). 원문의 「맨 위 카드가 중앙→오른쪽→중앙→왼쪽」은 이 규칙의 결과다.
- [원문·D-029] **쌓임 순서 불변식** — 합쳐질 때 두 뭉치가 한 장씩 엮이고 카드는 이웃과만 자리를 바꾼다.
  3은 2와 4 사이여야 하며 8 위로 올라가면 안 된다. 뭉치 단위로 통째로 위/아래가 되면 실패다.
  z 순서는 뭉치 단위가 아니라 **카드 단위**여야 하고, 이 불변식이 지켜지면 합쳐진 상태에서 8장의 테두리가 보인다.

| 순서 | 동작 | 시간 | 곡선 |
|---|---|---|---|
| 1 | 분리 (위 카드 오른쪽) | **150ms** | spring |
| 2 | 대기 | **100ms** | — |
| 3 | 합치기 | **100ms** | spring |
| 4 | 대기 | **70ms** | — |
| 5 | 분리 (위 카드 왼쪽) | **100ms** | spring |
| 6 | 대기 | **70ms** | — |
| 7 | 합치기 | **100ms** | spring |
| 8 | 4~7 한 번 더 반복 (분리 방향은 다시 오른쪽) | 340ms | spring |

- [도출] 4~7이 **2번 반복**이므로 분리는 총 3회, 합치기도 총 3회다. 섞기 구간 총길이는
  150+100+100+(70+100+70+100)×2 = **1,030ms**.

### 4.3 소멸 — 인터레이스로 좌우로 갈라져 사라진다

- [원문] 마지막 합치기가 끝난 뒤 **인터레이스 방식으로 좌우로 갈라지며 사라진다.**
- [원문] **페이드아웃과 움직임 모두 리니어.**
- [원문·D-015] 인터레이스 줄은 **약 10px 단위**로 묶는다(가늘면 페이드로 보인다).

### 4.4 사용자 결정이 필요한 미지정 값

원문이 정하지 않아 supervisor가 임의로 정하면 안 되는 값들이다. 슬라이더 기본값으로 아래를 제안하되
사용자가 보고 조정한다.

| 미지정 항목 | 제안 기본값 | 이유 |
|---|---|---|
| 모이기(8장 → 한 장) 지속 시간 | 150ms · spring | 분리·합치기와 같은 계열로 맞춤 |
| 소멸(인터레이스) 지속 시간 | 400ms · 리니어 | 페이드로 보이지 않을 만큼 짧고, 줄무늬가 읽힐 만큼은 긴 값 |
| 계단식 쌓기의 카드당 상단 오프셋 | 카드 높이의 2% | 8장이 쌓여도 덱 두께처럼 보이는 정도 |
| 낙하 시작 높이 | 카드 높이의 120% | "살짝 떨구듯" — 화면 밖까지 올리지 않는다 |
