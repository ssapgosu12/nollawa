# S6 — 점수판(스코어보드) 시장 조사

조사일: 2026-08-12 / 방법: 웹 검색(앱스토어·구글플레이 리스팅과 리뷰 요약, BGG 스레드, 제조사 랜딩 페이지) + 내부 지식
대상 축: 실물 보드게임·카드게임·주사위게임의 **점수 기록 앱** 시장. 수요 실체, 기존 구현, 리뷰 불만, 그리고
프로젝트가 판정을 요구한 두 질문 — (1) 공용 점수판 vs 개인 점수판, (2) 범용 하나 vs 게임별 전용.

> 용어 정리(이 문서 안에서만 쓰는 약칭)
> - **공용 점수판** = 기기 한 대를 테이블 위에 놓거나 돌려 가며 여러 사람의 점수를 다 입력하는 방식.
> - **개인 점수판** = 참가자 각자가 자기 폰을 들고 자기 점수만 입력하고, 그 결과가 어딘가에서 합쳐지는 방식.
> - **P2P 방 코드** = 서버 DB 없이 브라우저끼리 직접 연결(WebRTC)하고, 방 코드 6자리로 서로를 찾는 방식.
>   중앙 서버에는 "서로의 주소를 알려주는" 최소 신호 중계만 있고 점수 데이터는 저장되지 않는다.

## 0. 결론 요약 (먼저 읽을 것)

1. **이 프로젝트의 제약이 점수판 카테고리에서는 결함이 아니라 정확히 셀링포인트다.**
   무광고·무계정·오프라인·로컬저장·설치 불필요. 아래 §3에서 보듯 기존 점수판 앱 리뷰 불만의 1~3위가
   전부 광고·과금·계정/동기화다. 대전 게임 축(체스·오목 등)에서는 무서버 제약이 불리하게 작동하지만,
   점수판 축에서는 같은 제약이 그대로 경쟁 우위가 된다. **S6은 이 프로젝트가 시장 대비 가장 유리한 축이다.**

2. **수요는 압도적으로 공용 점수판이다.** 개인 점수판이 실제로 팔리는 시장은 골프와 리그·토너먼트 운영뿐이고,
   그 둘은 전부 **서버 리더보드**를 전제로 성립한다 → 본 프로젝트 제약 밖. 개인 기기 분산 입력이
   서버 없이도 정당화되는 유일한 경우는 **비공개 동시 입찰**(각자 몇 트릭 먹을지 남몰래 적고 동시 공개) 하나뿐이다.

3. **범용 하나로도 부족하고 전용만으로도 부족하다. 정답은 "범용 엔진 + 게임별 프리셋"이다.**
   전용 로직이 실제로 필요한 것은 규칙이 단순 덧셈을 넘어서는 6종뿐이다 — 요트, 마작(리치), 고스톱,
   다트(501/크리켓), 크리비지, 입찰 트릭. 나머지(카탄·루미큐브·훌라·원카드 등)는 범용 프리셋으로 충분하다.

4. **점수판의 생사는 정확성과 무손실이다.** 산술이 틀리거나 앱이 죽어 기록이 날아가면 그 앱은 끝난다.
   기존 앱 리뷰에서 가장 치명적인 불만이 정확히 이 둘이다(§3.1, §3.3).

## 1. 사람들은 점수 기록 앱을 왜 쓰는가 — 실제 동기

검색으로 확인된 사용 동기는 4갈래이고, 이 프로젝트가 겨냥해야 할 것은 ①②뿐이다.

| # | 동기 | 실체 | 본 프로젝트 적합 |
|---|------|------|-----------------|
| ① | **암산·필기 회피** | 요트 상단/하단 보너스, 고스톱 배수, 다트 501 차감, 마작 부·판 계산처럼 사람이 틀리기 쉬운 산술을 대신 시킨다 | ★ 최적합 |
| ② | **종이·연필·실물 점수판 부재** | 캠핑/카페/여행지에서 종이가 없다. 크리비지 보드나 마작 점봉을 안 가져왔다 | ★ 최적합 |
| ③ | **기록·통계 축적** | 승률, 누적 전적, 그래프. BG Stats류의 본진 | △ 로컬 저장으로 부분 가능(기기 1대 한정) |
| ④ | **원격 관전·중계** | 링크 하나로 다른 사람이 실시간 관전(KeepTheScore의 주력: 유소년 스포츠 중계, OBS 오버레이) | ✕ 서버 필요 → 제외 |

**핵심 반론도 함께 기록한다.** BGG 논의에서 반복되는 지적: *"펼쳐 둔 노트는 펜을 집어 쓰는 한 단계면 끝나고
방해도 없다. 짧은 게임은 종이가 더 빠르다"*, *"점수 앱은 종이보다 빠르고 편해야 한다 — 주인공은 게임이지
점수 앱이 아니다"*. 즉 **세팅에 다섯 탭이 필요한 순간 이 카테고리는 진다.**
설계 예산: 게임 시작까지 3탭 이내, 한 라운드 입력 1탭.

## 2. 어떤 게임의 점수판 수요가 큰가 (관측된 앱 밀도 기준)

앱스토어/플레이스토어에 **같은 게임 전용 점수판 앱이 여러 개 경쟁 중**이면 수요가 검증된 것으로 본다.

| 게임 | 관측 | 수요 판정 |
|------|------|-----------|
| **요트/야찌** | 전용 스코어카드 앱 최소 8종 확인(Yatzy Scorecard, Yahtzee Score Card, Scorecard for Yahtzee, Yatzy Scoring Card, Yahtzee ScoreKeeper 등) | **최상** — 카테고리 대표 |
| **다트** | Simple Darts 등 평점 4.2대 전용 앱군. 501 차감·크리켓 마크·더블/트리플 계산이 암산 부담 | **상** |
| **크리비지** | 페그보드 앱만 6종 이상(Cribbage Pegboard, Cribtastic, Cribbage Pegboard Tracker, Cribbage Board) | **상**(영미권) / 한국은 하 |
| **마작(리치)** | 점수 계산기 + 성적 관리가 분리된 두 시장 존재. 한국어 앱 "메모참새"(2025년 출시), 일본계 MemoJong, Reach Mahjong Score Manager 등. 공통 셀링 문구가 **"점봉(점수 막대) 교환의 번거로움 제거"** | **상**(한국 리치마작 인구 증가 중) |
| **고스톱/화투** | 점수 계산 *설명* 콘텐츠(brunch 등)는 대량이나, **점수판 앱은 희박**. 검색 상위는 전부 "고스톱 게임 앱"이고 실물용 계산·정산 앱이 안 잡힌다 | **중~상 · 공백 시장** |
| **당구(4구/3쿠션)** | 빌리보드 등 전용 앱. 스코어·애버리지·하이런 기록. 리뷰에 "여러 명이 칠 때 선수 선택 기록", "4구 경기 선택" 기능 요청 | **상**(한국 특수 수요) |
| **카탄** | 웹 전용 스코어카드가 난립(ScorecardGO, Score Door, ScoreApp.nl, catanscoreboard.com, SettlerStats). 대부분 "목표점 도달 카운터"에 불과 | **중**(단 상표 위험) |
| **루미큐브** | Rummikub Score Timer(iOS/Android) + 웹 Rummi Timer. **점수보다 "턴 타이머"가 핵심 셀링** | **중** |
| **골프** | 시장 자체는 거대(18Birdies, mScorecard, PlayThru, Squabbit, Golfify) | **최상이나 부적합**(§4 참조) |
| **훌라·원카드·스페이드·유커** | 전용 앱보다 범용 앱("Bids" 같은 입찰형 트래커)으로 흡수됨 | **중 · 범용으로 충분** |
| **범용(아무 게임)** | Keep Score(푸드네트워크 소개), Score Counter, 점수 카운터, Scory, 한국 "점수판" 앱 등 대량. 한국 시장에도 국산 범용 점수판 앱이 여럿 존재 | **최상 · 단 경쟁 포화** |

## 3. 기존 앱은 무엇에 실패하는가 — 리뷰 불만 지점 (설계 요구사항으로 직결)

### 3.1 산술 오류 — 가장 치명적
- 요트 앱에서 **열 합계가 틀림**: 1열 317 + 2열 306인데 앱은 623이 아니라 612로 표시, 그 오차가 전 열에 전파.
- 다른 요트 앱에서 **게임 반복 시 점수 배수 버그**: 1게임은 정상, 2게임째 2배, 3게임째 3배로 누적.
- Games Keeper: 다음 플레이어 화살표를 **빠르게 누르면 앞 사람 점수가 뒷사람에게 붙음**.
→ **요구사항**: 점수 계산은 "입력 이벤트 목록 → 순수 함수 → 총점"으로만 유도(누적 변수 금지, 게임 간 상태 초기화 보장).
  입력 이력을 전부 보관해 언제든 되돌리기(undo) 가능해야 하고, 총점 옆에 "어떻게 이 숫자가 나왔는지" 펼쳐볼 수 있어야 한다.

### 3.2 광고 — 종이보다 불편해지는 지점
- *"전면 광고가 방해되어 종이와 연필보다 불편하다"*, 개발자가 "유료로 광고 제거 가능"이라고 답하면 더 반발.
→ **요구사항**: 광고 0. 이것만으로 카테고리 상위권 앱들 대비 즉시 우위. 무료·무광고가 별점의 주된 칭찬 사유이기도 하다(Score Keeper 2020).

### 3.3 앱 종료 = 기록 소실
- 스크래블 도중 앱이 죽어 **전 점수 유실** 사례.
→ **요구사항(웹에서 더 중요)**: 브라우저 탭은 새로고침·백그라운드 종료가 앱보다 흔하다.
  **입력 1건마다 즉시 localStorage 커밋**, 재진입 시 "진행 중인 게임 이어하기" 복원 배너. 이건 부가기능이 아니라 1순위 요구사항.

### 3.4 과금 구조
- BG Stats: **유료 구매 후 또 인앱 결제**해야 전 기능을 쓴다는 불만이 반복.
→ 우리는 무과금. 언급 불필요할 정도의 우위.

### 3.5 UI 복잡도·발견성
- BG Stats: 잔기능이 많아 놓치기 쉽다("this is me" 설정을 안 하면 통계가 반쪽), 탐색이 헷갈린다, 동기화 문제.
- 어떤 앱은 업데이트 후 **확인·지우기·취소 버튼이 사라짐**, 글씨가 작아짐, 리셋 시 폰트가 초기화됨.
→ **요구사항**: 기능 최소. 그리고 **글자 크기는 우리 UI(흰 바탕·검은 선)의 핵심 자산**이다 — 테이블 위 1m 거리에서 읽혀야 한다.

### 3.6 다인 입력 흐름 붕괴
- 어떤 요트 앱은 **여러 명을 등록해도 플레이어 전환이 안 되어** 한 사람이 다 끝내야 하는 것처럼 동작.
- 당구 앱 리뷰의 기능 요청도 같은 계열: "여러 명일 때 선수를 선택해 기록하게 해달라".
→ **요구사항**: "지금 누구 차례인가"가 화면에서 즉시 보이고, 그 사람 칸만 활성화되며, 잘못 넣으면 되돌리기.

### 3.7 자동화 미흡
- 요트 앱 리뷰: **풀하우스·스몰/라지 스트레이트·요트는 고정 점수인데 왜 손으로 입력하게 하나**.
→ **요구사항**: 고정 점수 칸은 탭 한 번(체크) = 점수 확정. 숫자 키패드 호출 금지.

## 4. 판정 ① — 공용 점수판 vs 개인 점수판

### 근거

**공용이 시장의 기본형이라는 증거**
- 상위 범용 점수판 앱들(Keep Score, Score Counter, 한국 "점수판", 점수 카운터)은 전부 **단일 기기 다인 입력** 구조다.
- 크리비지 앱 Cribtastic이 대표 셀링포인트로 내세우는 것이 **"미러 레이아웃 — 두 플레이어가 각자 자기 쪽으로 바로 선 점수를 본다"**.
  이는 **기기 한 대가 테이블 가운데 놓여 있다**는 것을 제품이 전제한다는 직접 증거다.
- 마작 점수 앱들의 공통 문구가 "점봉 교환의 번거로움 제거"다. 점봉은 탁상 위 공용 물건이고, 그 대체물도 탁상 위 한 대다.

**개인 기기 분산 입력이 실제로 팔리는 곳 — 그리고 왜 우리와 무관한가**
- **골프**: PlayThru는 "링크를 골퍼와 관중 모두에게 공유, 앱 설치 없이 브라우저에서 열림", Squabbit은
  "경기 당일 각자 폰이나 워치로 기록, 링크·초대코드·QR로 참가, 다운로드·계정 불필요", Golfify는 "Google Cloud 기반 즉시 리더보드".
  → 셋 다 **실시간 리더보드 = 상시 서버**가 존재 이유다. 그리고 골퍼는 **물리적으로 흩어져 있다**(코스 18홀).
  같은 시장에서 mScorecard는 반대로 한 사람이 5명분을 한 폰에서 적는 전통형이며, 이쪽이 캐주얼 라운드의 기본값이다.
- **리그·토너먼트 운영**: 다트 리그, 골프 대회 등. 역시 중앙 집계 서버가 본질.

→ **한 테이블에 둘러앉은 사람들에게 개인 기기 분산 입력이 주는 이득은 사실상 없다.**
  오히려 손해다: 기기 4대가 다 켜져 있어야 하고, 연결이 끊기면 게임이 멈추며, 한 명이 화장실에 가면 점수가 안 들어간다.
  종이 점수표는 한 장이지 네 장이 아니다.

**개인 기기가 서버 없이도 정당화되는 유일한 경우**
- **비공개 동시 입찰**: 스컬킹·위저드·오헬 계열은 각자 "몇 트릭 먹겠다"를 **남에게 안 보이게 동시에** 정해야 한다.
  공용 기기 한 대로는 원리상 불가능(먼저 넣는 사람이 불리하거나, 남의 입찰을 보게 됨).
  현재 시장의 전용 앱들(Skull King Points, Skull King Scoring Companion, Wizard Score Pro)은 **전부 단일 기기**이고,
  입찰 비공개를 포기했거나 "종이에 적고 동시 공개" 아날로그 절차에 의존한다. → **여기가 진짜 공백이다.**
  검색으로 WebRTC 기반 다기기 비공개 입찰 도우미는 확인되지 않았다.
- 부차적으로: 8인 이상 대인원에서 기기를 8명이 돌리는 대기 시간을 없애는 용도. 다만 수요 근거는 약하다.

### 판정
> **기본형 = 공용 점수판(단일 기기, 테이블 중앙 거치).** 전 점수판 기능은 이 형태 하나로 완결되게 만든다.
> **개인 점수판은 독립 모드로 만들지 않는다.** 오직 **"비공개 입찰"이라는 단일 기능**으로만, 그것도
> P2P 방 코드 옵션(있으면 좋고 없어도 게임이 성립)으로 붙인다. 개인 점수판을 1급 시민으로 만드는 순간
> 연결·재접속·이탈 처리라는 유지보수 부채를 무서버 프로젝트가 떠안게 된다.

### 공용 전제에서 나오는 설계 요구 (기존 앱이 대부분 못 하는 것)
1. **테이블 거치 뷰**: 태블릿 가로 거치, 1m 거리에서 읽히는 큰 숫자. 흰 바탕·검은 선 UI가 여기서 가장 강하다.
2. **회전/미러**: 마주 앉은 사람 쪽 숫자를 180° 뒤집어 표시(Cribtastic이 증명한 수요). 2인 게임에서 특히.
3. **화면 꺼짐 방지**: 웹 점수판의 최대 실무 함정. Screen Wake Lock API로 처리하고, 미지원 브라우저용 폴백(무음 루프 등)을 준비하거나 최소한 "화면 자동 잠금 끄기" 안내를 띄운다.
4. **탭 종료 복원**: §3.3.

## 5. 판정 ② — 범용 점수판 하나 vs 게임별 전용

### 근거
- 웹 점수판 서비스들(ScorecardGO, Score Door, ScoreApp.nl)은 **게임별 랜딩 페이지를 대량 생성**한다
  ("Catan Score Tracker", "Catan Scorecard"…). 그러나 그 뒤의 엔진은 사실상 하나다.
  → **사용자는 "게임 이름"으로 찾아오지만, 필요한 것의 대부분은 공용 엔진으로 처리된다.**
- 반대로 요트·마작·다트·크리비지에 전용 앱이 여러 개씩 살아남아 있다는 사실은
  **규칙이 단순 덧셈을 넘는 게임은 범용으로 대체 불가**임을 보여 준다. 요트를 범용 점수판으로 적는 사람은 없다.

### 판정
> **범용 엔진 1개 + 전용 프리셋 6개.**
> 전용이 필요한 판별 기준은 딱 하나 — **"점수가 단순 합산이 아닌가?"**

| 전용 필요 (규칙 산술) | 이유 |
|---|---|
| 요트 | 칸별 판정 규칙 + 상단 보너스 63점 + 조커/보너스 |
| 다트 501·크리켓 | 차감식 + 더블 아웃 + 마크 3개 체계 |
| 크리비지 | 121점 트랙(페그) + 두 페그 표기 |
| 마작(리치) | 부·판 → 점수 표, 본장·리치봉·텐파이료 |
| 고스톱 | 점수 → 배수(피박/광박/고박/흔들기) → 판돈 정산 |
| 입찰 트릭 | 입찰값 vs 실제 트릭 수 대조 채점 |

| 범용 프리셋으로 충분 | 이유 |
|---|---|
| 카탄, 루미큐브, 훌라, 원카드, 당구, 스크래블, 그 외 대부분 | 라운드마다 숫자를 더하거나 빼는 것이 전부 |

**범용 엔진이 가져야 할 파라미터(이걸로 위 "충분" 칸이 전부 커버된다)**
- 점수 방향: 높을수록 승 / 낮을수록 승(훌라·원카드 계열은 감점제)
- 종료 조건: 목표점 도달(카탄 10점) / 정해진 라운드 수 / 수동 종료
- 입력 단위: 라운드별 표(세로 누적) / 즉석 +1 −1 카운터(당구·탁구형)
- 부가: 턴 타이머(루미큐브의 실제 킬러 기능), 딜러/선 표시, 라운드 메모

## 6. 이 프로젝트 제약과의 충돌 점검

| 제약 | 점수판 축에서의 영향 |
|---|---|
| 웹 PWA | **유리.** 설치 없이 링크로 즉시 = 카페·캠핑장에서 종이 대신 꺼내는 상황과 정확히 맞는다. PlayThru·Squabbit이 "무설치 브라우저"를 셀링포인트로 쓰는 것과 동일 논리 |
| 무서버·무DB | **점수판에서는 거의 무손실.** 잃는 것은 원격 관전 리더보드와 기기 간 전적 동기화뿐 |
| 로컬 저장만 | **주의 지점.** 전적 통계는 그 기기에서만 유효 → "이 기기의 기록"임을 명시. JSON 내보내기/가져오기로 완화 |
| 흰 바탕·검은 선 | **유리.** 실물 점수표의 시각 언어 그 자체. 테이블 거치 가독성 최강 |
| 4색(플레이어 1~4) | **부분 충돌.** 마작 4인·고스톱 3인·요트 4인은 문제 없음. 다트·범용은 5~8인 수요 존재 → 5인 이상은 색 대신 이름+번호로 구분(색 없이도 성립하게 설계) |
| 작은 세로 화면 | **주의.** 요트 세로 13칸×4열, 크리비지 121칸 보드가 압박. 요트는 "한 사람씩 크게 보기 ↔ 전체 표" 두 뷰가 필수 |
| 콘텐츠 유지보수 금지 | **골프 탈락의 직접 근거**(코스·홀·파·핸디캡 데이터를 계속 채워야 함). 나머지 후보는 전부 규칙=코드라 유지보수 0 |
| 상표 | 카탄·루미큐브·스컬킹·위저드·야찌(Yahtzee)는 상표. **게임 이름 대신 일반명으로 표기**("타일 러미 점수판", "입찰 트릭 점수판", "요트 다이스"). 고스톱·화투·마작·크리비지·다트·당구는 전통/일반명이라 안전 |

## 7. 우선순위 권고

**1군(즉시)**: 범용 점수판 엔진 + 요트 점수판(확정 코어의 실물 모드) + 다트 501/크리켓
→ 셋의 합이 시장의 대부분을 덮고, 셋 다 며칠 규모.

**2군(한국 특화 · 공백 시장)**: 고스톱 정산 점수판, 당구 점수판
→ 검색상 실물용 전용 앱이 얇다. 국내 수요 대비 공급이 가장 부족한 구간.

**3군(마니아 · 난이도 높음)**: 리치 마작 점수판, 크리비지 페그보드
→ 마작은 규칙 구현량이 크고 로컬룰 옵션이 지옥이라 별도 스프린트로 격리할 것.

**4군(차별화 실험)**: 입찰 트릭 점수판 + P2P 비공개 입찰
→ 이 프로젝트가 시장에 없는 물건을 내놓을 수 있는 유일한 지점.

**탈락**: 골프 스코어카드(코스 데이터 유지보수), BG Stats형 플레이 로그·컬렉션 관리(계정·클라우드·BGG 동기화), 원격 관전 리더보드(상시 서버).
