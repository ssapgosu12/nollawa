# S7 — 경쟁 서비스 빈틈 (Competitive gap analysis)

조사일: 2026-08-12 / 방법: 웹 검색(WebSearch) + 각 서비스 공개 문서·포럼 실측
판단 전제: 이 저장소의 프로젝트 제약(웹 PWA, 4모드[공용/스플릿/멀티 P2P/점수판], 무서버·무DB·무로그인,
로컬 저장만, 흰 바탕+검은 선+플레이어 4색, 폰/태블릿 양립, 유지보수 최소).

---

## 0. 결론 먼저 (포지셔닝)

경쟁 지형은 **세 덩어리**로 갈라져 있고, 그 사이에 우리 자리가 있다.

| 덩어리 | 대표 | 강점 | 구조적으로 안 하는 것 |
|---|---|---|---|
| A. 정통 온라인 대전 플랫폼 | BGA, Yucata, PlayOK, lichess, chess.com, OGS, 한게임/피망 | 게임 수·룰 강제·랭킹·매칭 | **한 기기 로컬 플레이**(공용/스플릿), **점수판**, 계정/서버 없는 운영 |
| B. 방코드 파티 서비스 | netgames.io, playingcards.io, jackbox.tv | 무로그인 즉시 시작, 폰=개인 화면 | **추상 2인 게임 없음**, 로컬 패스앤플레이 없음, AI 없음, **자기 서버 상시 운영 필요**, jackbox는 유료+콘텐츠 |
| C. 광고형 단품 사이트 | plays.org, arcadiagames.io, solitaireparadise, dotsandboxes.org, playquoridor.online 등 | 로컬 2인 플레이가 **있다** | 게임마다 딴 사이트·딴 UI, 광고, 오프라인/PWA 아님, 점수판 없음, P2P 없음 |
| D. 점수 기록 앱 | Keep Score, Scory, Score Pad, ScoreCount | 실물 게임 점수 기록 | 네이티브 앱 스토어 중심, **게임 룰과 무관한 범용 카운터**, 기기 간 공유 없음, **개인 점수판(각자 자기 것만) 개념 없음** |

**우리 자리 = A의 게임성 × C의 로컬 플레이 × B의 무로그인/방코드 를 하나의 무광고 PWA로 묶고,
아무도 통합하지 않은 D(점수판)를 네 번째 모드로 붙이는 것.**
특히 **개인 점수판(각자 기기에 자기 점수만 보이는 P2P 점수판)** 은 조사 범위 어디에도 없었다.

## 1. 서비스별 실측: 무엇을 하고 무엇을 안 하는가

### Board Game Arena (BGA)
- 제공: 700+ 라이선스 게임, 룰 완전 강제, 실시간/턴제, 브라우저만 있으면 됨.
- **안 함**: 계정 필수. 한 기기에서 두 사람이 번갈아 두는 로컬 모드 없음(모든 게임이 계정↔계정).
  프리미엄 게임은 "같은 IP면 프리미엄 1명으로 같은 테이블" 예외가 있을 뿐, 이는 로컬 플레이가 아니라
  과금 완화 장치다. 포럼에는 가족 단위 이용자가 아이들·조부모까지 각자 계정·프리미엄이 필요해
  불만을 제기한 사례가 있다(가족 계정 요청 스레드).
- 시사점: **"한 기기에 둘러앉기"라는 상황 자체가 BGA의 설계 밖**이다. 우리 (a)(b) 모드는 정면 충돌하지 않는다.

### PlayOK (구 kurnik)
- 제공: 23년 운영, 30+ 클래식(체스, 바둑, 오목, 백개먼, 도미노, 장기류 등). **게스트 모드로 무가입 즉시 대전**.
- **안 함**: 로컬 2인·점수판 없음. UI가 2000년대식, 모바일 최적화 빈약. 랭킹/친구는 가입 필요.
- 시사점: "무로그인 즉시 시작"은 PlayOK가 이미 한다 → **그것만으로는 차별점이 아니다.**
  차별은 *무로그인 + 한 기기 + 폰 UI + 오프라인 PWA*의 결합에 있다.

### lichess / chess.com
- lichess: 무로그인 대전 가능, 오픈소스, 최고 수준 체스. **모바일 앱에는 "Play offline → Over the board"(한 기기 2인)가 있으나 웹에는 없다.**
  웹 이용자는 analysis board를 편법으로 쓰고 자동 보드 회전 같은 게 없다고 포럼에서 반복 요청 중
  (lichess 포럼: "2 player chess on the same computer", "On same phone", "Over the board on PC" 등 다수 스레드).
- chess.com: pass & play 기능 존재(앱 중심), 계정·과금 유도 강함.
- 시사점: **"웹에서 되는 한 기기 대국"은 세계 최대 체스 사이트조차 비워둔 슬롯**이다. 확정 코어인 체스가
  이 축에서 바로 값을 낸다. 다만 우리는 강엔진 경쟁을 하지 않으므로 *로컬 2인*에만 집중해야 한다.

### OGS (online-go)
- 제공: 바둑 특화, 무료, 실시간/통신 대국, 리뷰. 계정 사실상 필수(대국·기보 저장).
- **안 함**: 한 기기 2인 대국, 점수판, 바둑 외 게임.

### netgames.io
- 제공: 4글자 방코드, **가입 없이** 폰만으로 원나잇 인랑·아발론·코드워드 등 사회적 추리 게임.
- **안 함**: 추상 2인 게임 없음, 로컬 패스앤플레이 없음, AI 없음, 점수판 없음.
  구조상 **자체 서버 상시 운영**(방 상태 서버 보유)이라 우리 제약(무서버)과는 다른 모델.
- 시사점: 이 영역(다수 인원 사회적 추리)은 이미 강자가 있고 콘텐츠 유지보수가 큼 → **우리가 들어갈 자리가 아니다.**

### playingcards.io
- 제공: 로그인 없이 방 생성·링크 공유, 카드/토큰 자유 배치 VTT, 커스텀 룸 제작.
- **안 함**: 룰 강제 없음(사람이 알아야 함), **폰에서는 글자가 작아 읽기 어렵다고 자사 FAQ가 인정**,
  방 보존은 계정/구독으로 차등(무계정 2주 후 삭제), 로컬 1기기 플레이 없음, 점수판 없음.
- 시사점: "작은 화면에서 성립하는가"가 실제 약점으로 확인된 사례. 우리의 폰 우선 설계가 유효한 차별.

### jackbox.tv
- 모델: **공용 큰 화면(호스트가 구매한 게임) + 각자 폰이 개인 화면**. 우리 (a)+(c) 혼합의 원형.
- **안 함**: 무료 아님(패키지 구매), 콘텐츠(문항·텍스트) 지속 제작이 본질, 보드게임 아님, 호스트가 PC/콘솔 필요.
- 시사점: **모델은 옳고 비용 구조가 다르다.** 우리는 같은 UX를 "폰/태블릿 한 대 + 방코드 P2P"로,
  콘텐츠 없는 룰 기반 게임에서 재현할 수 있다.

### 한게임 / 피망 / 카카오 채널
- 제공: 국내 웹보드 점유 압도적(고스톱·포커 중심). 카카오 연동 버전 존재.
- **안 함**: 무로그인 불가(카카오/밴드 계정 연동), 광고·아이템 과금, 사행성 규제 대상 장르, 앱 설치 유도,
  전통 보드게임(장기·윷놀이)조차 계정·앱 뒤에 있음.
- 시사점: **한국 이용자 기준 "가입도 광고도 없는 깨끗한 전통 게임 웹"이 사실상 비어 있다.**
  넷마블 윷놀이도 포털 계정 경로. 유일한 유사 사례가 개인 사이트 yutnori.olle.cc(P2P + AI 봇)로,
  이는 **수요 검증 신호이자 우리 모델이 실제로 작동한다는 실증**이다.

### Tabletopia / Yucata
- Tabletopia: 3D 샌드박스, **룰 강제 없음(설계상)**, 모바일 멀티는 이용자 평 "사실상 플레이 불가",
  UI 불만(라벨 없는 아이콘) 다수. 무거움 = 폰 제약과 정면 충돌.
- Yucata: 룰 강제 O, 게임 수 많음, 그러나 계정 필수·비동기 턴제 중심·UI 구식.
- 시사점: 둘 다 우리와 경쟁 축이 다르다. 우리가 "가볍고 즉시"를 잡으면 겹치지 않는다.

### 점수 기록 앱 / dice-roller 사이트
- Keep Score, Scory, Score Pad, Score Counter, ScoreCount.com 등 다수. 야찌·파클·크리비지·스카이조·
  다트·스크래블 등 "종이와 펜 대체" 수요가 크고 앱이 계속 나온다 = **수요는 확실하다.**
- **안 함**: 대부분 네이티브 앱(스토어 설치), 웹은 단순 카운터 수준. 게임 룰(야찌 족보 자동 계산 등)과
  대전 기능이 한 물건 안에 있는 사례가 드물다. **여러 기기에 나눠 띄우는 점수판·개인 점수판은 없음.**
  dice-roller 사이트들은 주사위만 굴리고 게임 상태를 모른다.
- 시사점: 우리의 (d) 점수판 모드는 **비어 있는 슬롯 + 유지보수 0(콘텐츠 없음)** 이라 가성비가 가장 높다.

## 2. 네 가지 축, 누가 하고 있나

| 축 | 하고 있는 곳 | 비어 있는 정도 |
|---|---|---|
| (1) 한 기기 공용(패스앤플레이) | lichess **앱만**, chess.com 앱, 광고형 단품 사이트(plays.org·freeboardgames.org·playpager 등), 네이티브 "2 Player Games" 앱 묶음 | **웹에서 통합 컬렉션으로는 사실상 없음.** 대형 플랫폼(BGA·Yucata·PlayOK·OGS)은 전무 |
| (2) 개인 기기 스플릿(화면 분할) | 네이티브 앱(Two Player Master, 2P Games 등 미니게임 묶음) | **보드게임에서는 거의 전무.** 웹은 더 비어 있음 = 가장 독창적 슬롯이자 검증 안 된 슬롯 |
| (3) 실물 게임 점수판 | 네이티브 점수 앱 다수, ScoreCount 등 웹 소수 | 범용 카운터는 포화 / **룰 연동 + 기기 분산 + 개인 점수판은 공백** |
| (4) 로그인 없는 즉시 시작 | PlayOK(게스트), netgames.io, playingcards.io, lichess, 광고형 단품 사이트 | **이미 흔하다 → 단독 차별점 아님.** "무로그인 + 무광고 + 오프라인 + 폰 우선"의 결합만이 차별 |

## 3. 그래서 무엇을 넣어야 하는가 (게임 선정 논리)

선정 기준은 "경쟁사가 안 하는 것"에 더해, 제약 4개를 실제로 통과하는지다:
**흑백 선화로 표현 가능한가 / 폰 세로 화면에 들어가는가 / 서버 없이 되는가 / 콘텐츠 유지보수가 0인가.**

- **통과가 쉬운 부류**: 격자·선·돌로 끝나는 추상 2인 게임(리버시·체커·사목·모리스·도트앤박스·헥스·울티밋 틱택토).
  전부 퍼블릭 도메인이고 흑백이 원형이며 보드가 작다. 광고형 단품 사이트에는 있지만 **하나의 무광고
  오프라인 컬렉션으로 묶인 곳이 없다.**
- **한국 특화 공백**: 윷놀이·장기. 국내 경로는 전부 계정/앱/광고 뒤에 있다. 윷놀이는 (a)(c)(d) 세 모드를
  전부 쓰는 유일한 게임이기도 하다(실물 윷 던지고 앱은 말판·점수만 담당하는 사용법 가능).
- **점수판 모드의 기둥**: 범용 라운드 점수판. 콘텐츠 0, 룰 0, 유지보수 0인데 실물 보드게임 전체를 커버한다.
- **감점/탈락 부류**:
  - 색이 정보인 게임(Qwixx류 롤앤라이트의 4색 행, 6색 이상 자원 게임) → 4색 제약과 충돌 + 대개 저작권 있음.
  - 텍스트 콘텐츠가 본체인 게임(코드네임즈류 단어, 퀴즈, 사회적 추리) → 유지보수 폭증 + netgames.io 선점 + 상표.
  - 현대 상업 게임(쿼리도·하이브·카탄 등) → 저작권/상표 리스크. 룰이 자유롭더라도 이름·아트·상표는 아니다.
  - 보드가 가로로 긴 게임(백개먼) → 폰 세로 화면에서 손해. PlayOK/BGA가 이미 충분히 커버 → 후순위.

## 4. 위험 메모
- **상표 주의**: "오델로"(메가하우스) → 리버시로 표기. "Connect Four"(해즈브로) → 사목/네 줄 잇기.
  "Quoridor"(Gigamic), "Codenames"(CGE), "Qwixx"(NSV)는 이름·구성물 모두 회피 대상.
  퍼블릭 도메인 확실군: 체스·바둑·오목·육목·체커·리버시(1880년대 룰)·나인 멘스 모리스·도트앤박스·
  헥스(룰 자체는 자유, 이름은 관용)·윷놀이·장기·요트(주사위 족보는 관용, "야찌" 상표만 회피).
- **스플릿 모드는 검증 부족**: 네이티브 미니게임 묶음 외 선례가 거의 없다 = 기회이자 리스크.
  사목·도트앤박스처럼 **정보가 전부 공개된 게임**부터 스플릿을 시험하고, 숨긴 정보가 필요한 게임은
  공용(가리고 넘기기) 또는 P2P 멀티로 보내는 게 안전하다.
- **P2P 시그널링은 최소 서버가 필요**: netgames.io/playingcards.io가 상시 서버를 가진 이유다.
  무료 시그널링만으로 버티는 설계(방코드 → 연결 후 서버 이탈)를 못 지키면 이 축의 우위가 무너진다.
