# S4 — 파티/다인 한 기기 (shared device) 조사

조사일: 2026-08-12 · 웹 검색 사용함(출처는 각 항목에 표기)
전제: 웹(PWA) · 흰 바탕 + 검은 선 + 플레이어 4색(노/빨/초/파) · 무서버 · 로컬 저장만 · 스마트폰 세로 화면에서도 성립 · 유지보수 최소화

---

## 0. 시장 실측 요약 (무엇이 실제로 쓰이는가)

### 0.1 "한 기기 여러 명"은 죽은 카테고리가 아니다 — 오히려 앱스토어 최상위 장르다
- **Stickman Party / 2 3 4 Player Games / 1 2 3 4 Player Games / Catch Party** 계열이 구글플레이·앱스토어에서 "한 화면 2~4인" 미니게임 모음으로 대형 카테고리를 형성. iOS "2 3 4 Player Games"는 40개, 안드는 30개 미니게임을 한 화면 분할·원터치 조작으로 제공.
  - <https://apps.apple.com/us/app/2-3-4-player-games/id1269516792>
  - <https://apps.apple.com/us/app/stickman-party-4-player-games/id1467762267>
  - <https://apps.apple.com/us/app/1-2-3-4-player-games/id1635978552>
  - 종합 리스트: <https://techwiser.com/games-you-can-play-on-same-device/>, <https://www.nextpit.com/best-multiplayer-games-on-single-smartphone>
- 시사점: **"화면을 나눠 각자 한 영역을 원터치로 두드리는 반응속도 대결"이 이 카테고리의 실질 코어**다. 이 프로젝트의 (b) 스플릿 모드와 정확히 일치하고, 콘텐츠 유지보수가 0이며, 흰바탕+4색 팔레트가 오히려 유리하다(플레이어 영역=색 구분이 색의 유일한 용도).

### 0.2 한국어권 직접 경쟁작 = PartyAt (핵심 벤치마크)
- <https://partyat.games/ko/> — "핸드폰 하나로 즐기는 오프라인 파티게임 앱(1~100인), 완전 오프라인·무료·회원가입 없음".
- 수록 게임 목록(실측): 익명 설문, 스무고개, 신경쇠약(메모리), 오델로, 사목(커넥트4), 넘버 마스터, 틱택토, 빙고, 친치로(주사위), 주사위, 룰렛, 폭탄 게임, 인랑(마피아), 그림 끝말잇기, 체커, 오목, 윙크 킬러, **워드울프**, 스피드, 바다거북 수프(예정), 만장일치(예정).
- 시사점 3가지:
  1. **"한 기기 파티앱"의 실제 구성비는 (심리전 역할 게임) + (2인 추상 보드) + (뽑기/룰렛 유틸)** 이다. 우리 확정 코어(체스·바둑·오목·육목·배틀쉽·요트)가 두 번째 칸을 이미 채우므로, S4가 채워야 할 것은 **첫 번째 칸(역할 배분 심리전)과 세 번째 칸(뽑기·타이머 유틸)**이다.
  2. 무서버·오프라인·무가입이 이 카테고리의 표준 셀링포인트 — 우리 제약과 충돌이 아니라 **일치**한다.
  3. 1~100인 표기는 "앱이 관리하는 인원"이 아니라 "앱은 진행 도구이고 사람은 무제한"이라는 뜻. 우리도 같은 설계를 취하면 3~8인 상한을 억지로 둘 필요가 없다.

### 0.3 무료 브라우저 파티게임 시장은 "각자 폰(멀티)" 쪽으로 쏠려 있다 — 여기가 빈틈
- GameBuddies.io / AirConsole / Gartic Phone / skribbl.io / jklm.fun(BombParty) / Kahoot 등 무료 브라우저 파티게임의 주류는 **"큰 화면 + 각자 폰이 컨트롤러"** 구조다.
  - <https://gamebuddies.io/jackbox-alternative>, <https://garticphone.com/>, <https://jklm.fun/>, <https://bombparty.io/>
  - Gartic Phone은 "다운로드/계정 없이 아무 기기 브라우저에서" 참가 — 단, **각자 자기 기기가 필요**하다(1기기 공용 불가).
- 반대로 **한 기기 패스앤플레이를 1급 모드로 내세운 웹 구현은 드물고, 있어도 영어권 단어 데이터에 묶여 있다.**
  - 예외적으로 존재: Spyfall(<https://thespyfall.com/> — "온라인 또는 폰 하나 돌려가며", 무설치·무가입), Pocket Party의 Spy Instant(<https://pocketparty.app/spy-instant> — "Pass & Play: 폰 하나가 돌면서 각자 역할을 비밀 확인"), Wavelength 로컬 모드(<https://www.huddlenight.com/games/wavelength>, <https://wavelengthgame.net/>), Snakes & Ladders/Ludo 로컬 6인(<https://snakesandladders.io/>, <https://robin-games.netlify.app/>).
- 시사점: **"한국어 + 한 기기 + 웹 + 무가입"의 조합은 실질적으로 비어 있다.** 우리가 채울 수 있는 자리다.

### 0.4 이 축 최대의 함정 = 콘텐츠 유지보수 (리뷰 실증)
- Heads Up!: 초기 구매 후에도 덱(단어 묶음)마다 추가 결제를 요구해 기만적이라는 불만이 다수. <https://mwm.ai/apps/heads-up/623592465>
- Taboo(앱판): **"유료 앱이 같은 100단어를 계속 돌려서 다들 외워 버린다"** — 단어 반복이 핵심 불만. <https://mwm.ai/apps/taboo/1563932741>
- 경쟁 대응이 전부 "덱 48개·6,500문항" 같은 **물량 경쟁**으로 흐른다. <https://apps.apple.com/app/id6752926034> (Guessly)
- 결론: **단어·질문 카드를 소비하는 게임은 이 프로젝트에서 구조적으로 진다.** 물량 경쟁에 참여할 수 없기 때문이다. 따라서 이 축의 채택 원칙은 다음 셋 중 하나여야 한다.
  - (A) **콘텐츠 소비량 0** — 규칙과 타이머만으로 성립(폭탄 돌리기, 반응속도, 훈민정음, 뽑기).
  - (B) **콘텐츠를 플레이어가 즉석 입력** — 제시어를 사람이 넣는다(텔레스트레이션, 페이크 아티스트).
  - (C) **유한·불변 집합** — 한글 자모, 숫자, 카드 52장처럼 늘릴 필요가 원천적으로 없는 것.
  - 위 셋에 안 들면 fit_score 3 이하로 강등.

### 0.5 그 밖에 확인된 제약 접점
- **비밀 정보 전달 문제**: 한 기기 심리전(스파이·마피아·워드울프)의 UX 핵심은 "다음 사람에게 넘기기 전에 화면을 확실히 가리는 것". 실제 구현들이 전부 *탭 유지(hold-to-reveal) → 손 떼면 즉시 가림 → "다음 사람에게 전달" 전면 차단 화면*을 쓴다. 이건 흰바탕/검은선으로 만들기 쉽고 유지보수가 없다.
- **iOS 웹 센서 제약**: 이마고(폰을 이마에 대고 기울여 정답/패스)는 `DeviceOrientationEvent`가 iOS Safari에서 사용자 제스처 기반 권한 요청을 요구하고 거부 시 동작 불가 → 폴백(화면 상/하단 탭)이 반드시 필요. PWA에서 웹으로 하려면 감점 요인.
- **화면 회전/절전**: 파티 게임은 오래 화면을 켜 두므로 Wake Lock API 필요(미지원 브라우저 폴백=무음 비디오 루프). 전 게임 공통 인프라로 한 번만 만들면 됨.
- **동시 다중 터치**: 4인 동시 터치는 iOS Safari에서도 `touchstart` 다중 포인터가 정상 동작하나, **폰 세로 화면에서 4인은 물리적으로 불가**(손이 안 들어감). 폰=2인, 태블릿=4인으로 모드를 분기해야 한다.

## 1. 채택 후보 상세

### 1-A. 콘텐츠 소비 0 그룹 (최우선 채택)

#### 1. 폭탄 돌리기 (핫 포테이토)
- 방식: 실물 폰을 손에서 손으로 돌린다. 랜덤 시각(예: 20~60초 사이 비공개)에 폭발음 → 들고 있던 사람 패배.
- 근거: PartyAt "폭탄 게임" 1~100인 수록. 한국 앱 "추첨이"도 폭탄 게임을 6종 중 하나로 수록(<https://apps.apple.com/kr/app/id1488932068>). Bomb Party 계열이 앱/웹 양쪽에서 지속 수요(<https://bombparty.io/>, <https://apps.apple.com/us/app/bomb-party-hot-potato/id1608781349>).
- 제약 적합: 화면=큰 원 하나 + 타이머 없음(비공개). 색 불필요. 세로 폰 완벽. 콘텐츠 0. 구현 반나절.
- 변형(선택): "주제 제시 + 대답해야 넘김"을 붙이면 재미가 크게 오르나 주제 카드=콘텐츠. → **주제는 사용자가 직접 입력하는 칸으로 제공**(0.4의 B 원칙).
- 위험: 실물 폰을 던지듯 넘기다 낙하 파손. 경고 문구 1줄로 대응. 소리 필요(무음 모드 대비 진동 폴백).

#### 2. 훈민정음 / 금칙 글자 심판
- 방식: 앱이 금지 글자(예: "ㄱ" 들어간 말 금지, 또는 특정 음절)를 랜덤 지정하고 라운드 타이머를 잰다. 판정은 사람이, 기록만 앱이.
- 근거: 한국 술자리 게임의 정번. PartyAt이 같은 성격(그림 끝말잇기·워드울프)을 수록. 이 계열은 앱이 "심판·타이머" 역할만 해도 성립한다는 것이 PartyAt·추첨이 구성에서 확인됨.
- 제약 적합: 한글 자모 = 유한 불변 집합(0.4의 C). **콘텐츠 유지보수가 원리적으로 0.** 화면=큰 글자 하나. 폰 세로 최적. 구현 반나절.
- 위험: 거의 없음. 다만 "게임"이라기보다 진행 도구 — 단독 메뉴 항목으로는 존재감이 약하므로 "심판 도구" 묶음으로 묶는 편이 낫다.

#### 3. 동시 터치 반응속도 대결 (화면 분할 2~4인)
- 방식: 화면을 2/3/4분할, 각자 영역 담당. 신호가 뜨면 먼저 누른 사람 승. 페이크 신호·색 매칭·연산 문제 등 규칙 변주 5~8종.
- 근거: 이 축 시장의 코어(0.1). Stickman Party·2 3 4 Player Games가 40여 미니게임으로 대형 다운로드를 확보한 형식이고, 그 중 반응속도가 가장 많이 인용되는 서브장르(<https://www.twoplayergames.org/touch-screen>).
- 제약 적합: **이 프로젝트 팔레트와 가장 잘 맞는 게임.** 색의 유일한 용도가 "플레이어 1~4 구분"인데 이 게임이 정확히 그 용도만 쓴다. 콘텐츠 0. 스플릿 모드의 대표작.
- 위험: 폰 세로에서는 2인이 상한(물리적 손 공간). 4인은 태블릿 전제 → 모드 분기 필요. 기기별 터치 지연 차이는 같은 기기라 공평(오히려 장점).

#### 4. 랜덤 뽑기 세트 (사다리 타기 · 룰렛 · 술래 정하기 · 손가락 뽑기)
- 방식: 벌칙자/순서/팀 결정 유틸. "손가락 뽑기"=여러 명이 화면에 동시에 손가락을 올리면 랜덤 1명 선택.
- 근거: 한국 앱 "추첨이 – 파티 게임"이 악어 치과·사다리·룰렛·병 돌리기·폭탄·주사위 6종으로 구성(<https://apps.apple.com/kr/app/id1488932068>). PartyAt도 룰렛·주사위를 별도 수록. **파티 세션의 진입점 역할**을 하므로 체류가 아니라 유입에 기여.
- 제약 적합: 콘텐츠 0, 흰바탕+검은선으로 사다리·룰렛 모두 표현 가능, 구현 반나절~1일.
- 위험: 게임성이 낮아 단독 가치가 작다. 다른 게임의 "선공 정하기"에 내장 호출되게 만들면 가치가 커진다.

#### 5. 눈치게임 (동시 터치판)
- 방식: 각자 화면 한 구역을 잡고, 1부터 순서 없이 아무나 누른다. 동시에 눌리면 그 둘이 탈락. 마지막 1명 패배.
- 근거: PartyAt 소개문이 "워드 게임, **눈치싸움**, 순발력 게임, 클래식 보드게임"을 4대 축으로 명시 — 한국어권 파티앱의 정식 카테고리.
- 제약 적합: 콘텐츠 0. 4색 = 플레이어 구분에만 사용. 태블릿 4인 최적, 폰은 3인까지 빠듯.
- 위험: 동시 입력 판정 창(예: 150ms)의 튜닝이 재미를 좌우 — 값 하나로 게임이 죽거나 산다. 실측 필요.

### 1-B. 콘텐츠를 플레이어가 입력하는 그룹 (채택 권장)

#### 6. 스파이 / 워드울프 (패스앤플레이 역할 배분)
- 방식: 폰을 돌리며 각자 자기 단어(또는 "당신은 스파이")를 비밀 확인 → 토론 → 지목.
- 근거: thespyfall.com이 "온라인 **또는 폰 하나 돌려가며**"를 전면에 내세운 무설치·무가입 웹 구현(<https://thespyfall.com/>). Pocket Party는 Pass & Play를 별도 기능으로 명시(<https://pocketparty.app/spy-instant>). PartyAt은 워드울프를 1~100인으로 수록. 한국어 전용 "워드울프" 앱은 3,000종 이상 테마를 광고할 만큼 시장이 형성(<https://play.google.com/store/apps/details?id=com.wordwolf.sympathy>).
- 제약 적합: 화면=텍스트 한 줄 + hold-to-reveal. 폰 세로 최적. 3~8인이 정확히 이 게임의 스윗스팟. 구현 1~2일.
- 위험: **단어쌍이 콘텐츠다.** 다만 (a) 300쌍이면 수십 세션을 버티고 (b) "직접 단어쌍 추가" 입력을 제공하면 유지보수를 사용자에게 이양할 수 있다. 경쟁작의 "3,000테마" 물량과 싸우지 말 것.

#### 7. 텔레스트레이션 (그림 전화, 패스앤플레이)
- 방식: 제시어 → 그림 → 다음 사람이 그림만 보고 단어 추측 → 그 단어로 다음 사람이 그림 … → 마지막에 전 과정 리플레이.
- 근거: 단일 기기 패스앤플레이 구현이 실제로 존재하고 평가도 좋다 — TeleDraw: Telephone Pictionary, 4.5★ / 108리뷰(<https://apps.apple.com/us/app/teledraw-telephone-pictionary/id6615065956>). 웹 주류인 Gartic Phone(<https://garticphone.com/>)은 **각자 기기 필요** → 한 기기 시장은 상대적으로 비어 있다.
- 제약 적합: **흰 바탕 + 검은 선이 그대로 게임 규칙이 된다** — 이 프로젝트 미학과 가장 잘 맞는 후보. 제시어를 첫 플레이어가 직접 입력하게 하면 콘텐츠 0.
- 위험: (a) 이전 단계 노출 차단 UX(전달 차단 화면) 필수, (b) 그림 데이터 누적 → IndexedDB 사용 + 세션 종료 시 정리, (c) 폰 세로 캔버스가 작다(태블릿 우대), (d) 구현 난도가 이 축에서 가장 높음(캔버스 + 릴레이 + 리플레이). 실측 근거로는 TeleDraw 리뷰에서 **계정 요구가 불만 1순위** — 우리는 계정이 없으므로 그 지점이 그대로 차별점.

#### 8. 페이크 아티스트 (한 획씩 그리기 + 정체 숨기기)
- 방식: 폰을 돌리며 한 사람당 선 하나씩. 한 명만 제시어를 모른다. 두 바퀴 후 지목.
- 근거: 무료 브라우저 파티게임 정리 기사들이 Fake Artist Online을 Wavelength와 함께 "완전 무료·무설치·무계정"의 대표로 반복 인용(<https://gamesocial.io/games-like-jackbox-the-best-party-game-alternatives-for-2025/>, <https://www.cbr.com/jackbox-free-alternative-party-games/>).
- 제약 적합: 흰바탕/검은선 그대로. 선 색만 플레이어 4색. 제시어는 "출제자 1명이 입력" → 콘텐츠 0.
- 위험: 5인 이상이면 4색 팔레트로 필기자 구분이 부족 → 선 스타일(점선·이중선)로 확장 필요. 캔버스 구현이 7번과 공유되므로 7번과 묶어서 개발하면 총비용 절감.

#### 9. 사회자 없는 마피아 / 원나잇 인랑
- 방식: 폰 하나가 사회자. 역할 비밀 배분 → 밤 진행 안내 → 낮 토론 타이머 → 투표 집계.
- 근거: 구글플레이 "사회자 없는 마피아 게임"(<https://play.google.com/store/apps/details?id=llc.aves.mafia>)이 정확히 한 기기 진행 방식. PartyAt도 인랑을 1~100인으로 수록. 마피아42 같은 서버형 대작이 따로 있다는 것은 **오프라인 대면 진행 수요가 별개로 존재**한다는 방증.
- 제약 적합: 역할 세트는 고정(유한 집합) → 콘텐츠 0에 가깝다. 3~8인 정확 일치. 화면=텍스트 위주라 폰 세로 최적.
- 위험: 밤 진행 안내가 **음성**이면 좋은데 웹 TTS는 브라우저별 한국어 음질 편차가 크고 오프라인 보장이 안 된다 → 텍스트+효과음 진행으로 설계하고 TTS는 선택 기능. 라운드 상태 기계가 이 축에서 두 번째로 복잡.

### 1-C. 콘텐츠 리스크로 감점되는 그룹 (조건부)

#### 10. 이마고 / 헤즈업 (폰을 이마에)
- 근거: 웹 무료 구현이 이미 다수 — upheads(30덱·1,600단어, <https://upheadsgame.com/>), Pick The Wheel(<https://pickthewheel.com/heads-up-game/>). 즉 수요는 확실하나 **경쟁이 물량으로 붙어 있는 시장**.
- 감점 사유 셋: (1) 단어 = 순수 소비 콘텐츠, 경쟁작이 1,600~6,500문항으로 물량전(0.4). (2) iOS 웹 센서 권한 문제로 기울임 조작이 불안정 → 탭 폴백 필수. (3) 가로 고정 + 큰 글자 = 우리 UI 원칙과는 맞지만 화면 회전 잠금 제어가 웹에선 제한적.
- 채택한다면: 단어팩을 **사용자 직접 입력/편집 전용**으로 만들고 기본 팩은 최소로 — 물량전에 참전하지 않는다.

#### 11. 웨이브렝스 (스펙트럼 다이얼)
- 근거: 무료 웹 구현이 난립할 만큼 인기(<https://www.wavelength.zone/>, <https://wavelengthgame.net/>, <https://www.huddlenight.com/games/wavelength>), **로컬 패스앤플레이 모드도 명시적으로 존재**. 4~12인 권장으로 우리 3~8인과 겹침.
- 제약 적합 부분: 반원 다이얼 = 흰바탕/검은선으로 아름답게 나온다. 구현 난도 낮음(다이얼 + 점수).
- 감점 사유: **스펙트럼 카드쌍(뜨겁다↔차갑다 류)이 전부 콘텐츠이고 한국어 번안이 필요**하다. 한 번 본 카드는 재미가 반감 → 소비 속도가 빠르다. 사용자 입력 대체가 어려움(좋은 스펙트럼 쌍을 즉석에서 만들기 힘들다).

#### 12. 끝말잇기 / 초성 릴레이 (심판형)
- 근거: PartyAt "그림 끝말잇기" 수록. jklm.fun BombParty(<https://jklm.fun/>)가 같은 메커니즘의 세계적 성공 사례(단 각자 기기·타이핑 전제).
- 두 갈래:
  - (a) **심판형(권장)**: 사람이 말로 하고 앱은 타이머·순서·초성 제시만. 콘텐츠 0, 구현 반나절.
  - (b) **사전형**: 한국어 사전 내장 판정. 용량 수 MB~수십 MB, 두음법칙·한방단어 논쟁, 사전 갱신 = 유지보수. 감점.
- 채택 시 (a)로 한정.

### 1-D. 탈락 (근거를 남기기 위해 기재)

#### 13. "우리 중 누가 제일 ~할까" / 익명 설문 계열
- 근거: PartyAt이 "익명 설문"을 대표 게임으로 첫 줄에 배치할 만큼 인기 형식.
- 탈락 사유: **질문 카드가 곧 게임의 전부**이며 소비 속도가 이 축에서 가장 빠르다(한 세션에 30~50문항). Taboo의 "같은 100단어를 다들 외워 버린다" 불만이 그대로 재현될 형식. 게다가 한 기기에서 비밀 투표를 하려면 패스앤플레이를 인원수만큼 반복해야 해 진행이 느리다. → fit 2.

#### 14. 부루마블류 (주사위 이동 + 자산 관리 보드)
- 근거: 로컬 6인 패스앤플레이 보드 웹 구현 자체는 존재(<https://snakesandladders.io/>, <https://robin-games.netlify.app/>) — 즉 기술적 불가능이 아니라 **적합성** 문제.
- 탈락 사유 넷: (1) "부루마블"은 한국 등록 상표이고 모노폴리도 상표 — 이름·보드 디자인 사용 불가, 재구성 필요. (2) 보드 40칸 + 자산 + 잔액 + 건물 = **정보 밀도가 이 축에서 최악**, 폰 세로에서 성립하지 않는다. (3) 색이 부동산 그룹 8색 이상을 요구 → 4색 팔레트 원칙과 정면 충돌. (4) 1판 60분+ = 파티 리듬과 불일치, 구현은 주 단위. → fit 1.
- 남길 것: **주사위 굴려 이동하는 단순 레이스(사다리 게임류)**는 위 문제가 없으므로 필요하면 그쪽으로 대체할 것. 단 게임성이 낮아 별도 채택 가치는 크지 않다.

## 2. 개발 순서 제안 (이 축 한정)

1. **공통 인프라 1회**: 화면 꺼짐 방지(Wake Lock + 폴백) · 플레이어 등록(이름/색 4종) · 패스앤플레이 전달 차단 화면(hold-to-reveal) · 랜덤 시드. → 이후 게임 대부분이 이것만 재사용한다.
2. **1일급 4종 동시 투입**: 폭탄 돌리기 · 훈민정음 심판 · 뽑기 세트 · 눈치게임. 콘텐츠 0이라 유지보수 부채가 안 생긴다.
3. **스플릿의 대표작**: 반응속도 대결(변주 5종). 태블릿 4인 / 폰 2인 분기.
4. **심리전 1종**: 스파이·워드울프(사용자 단어쌍 추가 지원).
5. **캔버스 묶음**: 페이크 아티스트 → 텔레스트레이션(같은 캔버스·릴레이 코드 공유).
6. 이마고·웨이브렝스는 **콘텐츠를 사용자 입력으로 돌릴 방법이 확정된 뒤에만** 착수.

## 3. 이 축의 한 줄 결론
경쟁작들이 전부 **단어 물량**으로 싸우고 있고, 우리는 그 싸움에 참전할 수 없다. 대신 **규칙과 타이머만으로 성립하는 게임(폭탄·훈민정음·반응속도·눈치·뽑기)과 제시어를 사람이 넣는 게임(텔레스트레이션·페이크 아티스트)**으로 축을 구성하면, 유지보수 0을 지키면서 한국어 + 한 기기 + 웹 + 무가입이라는 실제로 비어 있는 자리를 차지할 수 있다.
