# S9 — 라이선스 위험 (상표·저작권) 판정

작성: 2026-08-12 / 웹 검색 사용함(출처는 문서 하단 및 각 항목 인라인)

---

## 0. 한 줄 결론

**규칙은 자유, 이름은 위험, 그림·판·문구는 더 위험.**
이 프로젝트가 지켜야 할 것은 딱 세 줄이다.

1. 상용 게임의 **이름을 앱/페이지 제목·메뉴·URL·메타태그·스토어 키워드 어디에도 쓰지 않는다.**
2. **"○○ 스타일", "○○처럼", "Yahtzee-like"** 같은 비교 문구도 쓰지 않는다(가장 흔한 사고 지점).
3. 이름을 바꿔도 **판 그림·카드 텍스트·아이콘·색 배치를 베끼면 여전히 걸린다.** 판정 기준은 "이름"이 아니라 "이름 + 겉모습(trade dress)" 둘 다다.

---

## 1. 법적 뼈대 — 무엇이 보호되고 무엇이 안 되는가

### 1.1 보호되지 **않는** 것 (자유롭게 구현 가능)
- **게임 규칙·진행 방식·메커니즘 그 자체.** 미국 저작권청 입장이자 판례의 확립된 태도다. "누군가 당신의 룰북을 읽고 거의 동일하게 플레이되는 게임을 만들어도, 문장·그림·구성물을 베끼지 않는 한 합법"이라는 것이 실무 요약이다.
  (출처: American Bar Association *Not Playing Around: Board Games and IP Law*, Meeple Mountain 디자이너 IP 가이드)
- **게임의 아이디어·제목 그 자체는 저작권 대상이 아니다**(제목은 저작권이 아니라 상표로 다룬다).

### 1.2 ★한국 판례 — 규칙은 저작권 보호 대상이 아니다 (직접 적용됨)
**부루마블(아이피플스) vs 모두의마블(넷마블), 서울중앙지법, 원고 패소(50억 청구).**
법원 판단 요지:
- "부루마불에 적용된 **규칙과 경기 진행 방식은 저작권법의 보호 대상이 아니다.**"
- "사각형 틀에 땅을 나누고 주사위를 던져 이동하는 방식은 **널리 알려진 경기 규칙**이다."
- 다만 "게임판 칸의 **지명·랜드마크·무인도 등 특수한 규칙**"에는 보호 대상이 다수 존재한다고 명시 — 즉 **구체적 표현(칸 이름, 지명, 아트)은 베끼면 안 된다.**

→ 이 프로젝트에 주는 함의: **한국 법정에서도 "말판을 돌며 땅 사기" 규칙 자체는 자유.** 위험은 오로지 이름(부루마블/모노폴리)과 칸에 적은 지명·아트에 있다.

### 1.3 보호되는 것 (건드리면 안 됨)
| 대상 | 보호 수단 | 이 프로젝트에서의 위험 |
|---|---|---|
| 게임 이름(YAHTZEE, BATTLESHIP, MONOPOLY, UNO, JENGA, CATAN, RUMMIKUB, OTHELLO, SCRABBLE, CODENAMES, CONNECT 4) | 상표 | **최상.** 앱 제목·메뉴 라벨 한 줄이면 성립 |
| 룰북 문장, 카드 텍스트, 칸 이름 목록 | 저작권 | 높음(콘텐츠를 베껴 넣을 유인이 큼) |
| 판 그림·말 모양·박스 아트·아이콘 | 저작권 | 중간(우리는 흰바탕/검은선 자작이라 회피 쉬움) |
| **전체 겉모습**(배치·색조합·타일 패턴) = trade dress | 상표/부정경쟁 | **중간~높음. 이름을 바꿔도 남는 위험.** |

## 3. 실제 takedown 사례 (근거)

### 3.1 Scrabulous → Wordscraper/Lexulous (2008) ★이 프로젝트에 가장 중요한 판례
- 2008년 7월 Hasbro가 페이스북 앱 *Scrabulous* 제작자(인도 Agarwalla 형제, RJ Softwares)를 뉴욕 연방법원에 제소. 페이스북은 미국·캐나다에서 앱 차단, 이후 전세계 차단(인도 제외 — 그 지역 권리는 Mattel).
- **결말이 핵심**: 2008년 12월 Hasbro가 **소를 취하**했다. RJ Softwares가 ①"Scrabulous" 명칭 사용 중단 ②게임을 **Wordscraper / Lexulous로 변경**하면서 **보드 배치 등 표현을 Scrabble과 구별되게 수정**하는 데 합의했기 때문.
- **판정**: 이름 변경은 효과가 있다. **단, 이름만으로는 부족했다** — 권리자가 만족한 것은 이름 + 판의 겉모습을 함께 바꿨을 때였다.

### 3.2 NYT vs Wordle 클론 (2024) ★"이름을 안 써도 걸릴 수 있다"의 실증
- NYT가 2024년 1월 2일부터 GitHub에 DMCA 통지, **약 1,900개 저장소**를 대상으로 함. Reactle(Chase Wackerfuss) 등이 표적. 호주 영어판·요루바어판 제작자도 통지 받음.
- 통지 근거가 **"Wordle 이름" + "look and feel — 초록/회색/노랑 타일의 레이아웃과 배색"** 둘 다였다는 점이 중요하다.
- **판정**: 단어 맞히기 규칙은 자유지만, **6줄×5칸 격자 + 초록/노랑/회색 조합을 그대로 쓰면 이름을 바꿔도 통지 대상이 된다.** 우리 프로젝트는 흰바탕/검은선 원칙이 오히려 방어막이 된다(정답=채움, 위치오답=테두리 등 **형태로 구분**).

### 3.3 Catan GmbH vs *Island Settlers* (안드로이드 팬앱, 2011) ★배포 형태가 우리와 동일
- 무료 안드로이드 팬앱에 대해 Catan 측이 저작권+상표 양쪽을 주장해 내림. Public Knowledge·Techdirt는 "법적 근거가 약한 과잉 주장"이라고 비판했지만 **앱은 실제로 내려갔다.**
- **판정**: 옳고 그름과 무관하게, **개인이 스토어/호스팅에서 버티는 비용이 권리자보다 훨씬 크다.** 이 프로젝트는 다투지 않고 회피하는 전략만 유효하다.

### 3.4 Czech Games Edition vs 온라인 Codenames 클론 (2020)
- CGE가 온라인 클론과 그 GitHub 저장소 내림을 요청, 제작자가 응함.
- **판정**: "보드게임 회사는 온라인 팬 구현을 봐준다"는 통념은 사실이 아니다. 현행 상용 게임(2010년대 이후 출시)일수록 위험이 높다.

### 3.5 플랫폼의 처리 방식 (배포 리스크)
- Google Play는 상표 침해 앱을 허용하지 않으며 **IP 신고 창구**를 운영한다. DMCA는 저작권 전용이라 상표는 별도 절차지만, 플랫폼은 자체 정책으로 내린다.
- **DMCA에는 상표 조항이 없다**(Odin Law). 즉 상표 문제는 "통지-반박" 절차 없이 **플랫폼 재량 삭제 → 사후 이의제기**로 흘러 개발자에게 더 불리하다.
- 우리는 웹(PWA) 우선이라 스토어 심사를 피하지만, **정적 호스팅(GitHub Pages/Netlify/Vercel)도 상표 신고로 내려간다.** GitHub은 Wordle 사례에서 1,900개를 처리했다.

## 4. "이름을 바꾸면 안전해지는가" — 구체 판정

| 상황 | 판정 |
|---|---|
| Yahtzee → **요트 다이스** | ✅ **안전.** 점수 항목(Ones~Chance, 33+35 보너스, 4개 동일 등)은 퍼블릭 도메인 Yacht/Yatzy에도 존재하는 규칙이며 규칙은 보호 대상이 아니다. **단 점수표 항목 이름을 "야찌"로 쓰면 안 된다** → "동일 5개" 또는 "요트"로. |
| Battleship → **함대 격침** | ✅ **안전.** 10×10 격자·5척 배치·명중/빗나감은 1931년 Salvo까지 거슬러 가는 퍼블릭 도메인 규칙. 빨간/흰 페그의 **플라스틱 케이스 외형**만 피하면 된다(우리는 어차피 흰바탕/검은선). |
| Othello → **리버시** | ✅ **완전 안전.** 업계 표준 회피법이며 규칙 변경도 불필요. |
| Connect 4 → **사목 / 네 줄 잇기** | ✅ **안전.** 단 "빨강 vs 노랑 원판이 격자에 떨어지는" 그림을 그대로 재현하지 말고, 우리 4색 규칙(플레이어 색)으로 자연스럽게 흡수. |
| Mastermind → **숫자 추리(불즈 앤 카우스)** | ✅ **안전 + 오히려 유리.** 원작의 6색 페그는 우리 UI 규칙(색은 플레이어 구분 전용)과 충돌 → **숫자 4자리**로 하면 상표 회피와 UI 규칙 준수가 동시에 달성된다. |
| UNO → **크레이지 에이트** | ⚠️ **조건부 안전.** 이름과 규칙은 안전하지만, **UNO 전용 카드의 겉모습**(검정 배경 타원 로고, Skip/Reverse/Wild 아이콘, 빨/노/초/파 4색 카드)을 재현하면 trade dress 문제. 표준 52장 트럼프(♠♥♦♣) 표기를 쓰면 완전 회피. |
| Scrabble → **낱말 타일** | ❌ **이름 변경만으로 불충분.** Scrabulous 합의가 **보드 배치까지 바꾼 뒤에야** 성립했다. 15×15 판의 **프리미엄 칸(2배/3배 단어·글자) 배치 패턴 자체가 저작물성 있는 표현으로 다뤄졌다.** 우리 판을 쓰려면 칸 배치를 독자적으로 재설계해야 하고, 그 시점에서 "익숙한 게임"이라는 효용이 사라진다. |
| Monopoly/부루마블 → **부동산 말판** | ⚠️ **규칙은 한국 판례상 안전, 그러나** 칸의 **지명·랜드마크 목록**을 베끼면 판례가 명시적으로 "보호 대상 다수 존재"라 한 부분에 정확히 걸린다. 지명을 전부 창작해야 한다. |
| Wordle → **다섯 글자** | ⚠️ **이름 + 배색 둘 다 바꿔야 안전.** 초록/노랑/회색 타일 조합 금지. |
| Catan → 임의 개명 | ⚠️ 규칙(육각 타일·자원 교역·건설)은 원리상 자유지만 **권리자가 실제로 팬 구현을 내리는 이력**이 있고, 6종 자원 색 구분이 우리 UI 규칙과도 정면 충돌. **채택 자체를 권장하지 않는다.** |
| Codenames → 임의 개명 | ⚠️ 규칙 자유·실제 takedown 이력 있음 + **단어 카드 콘텐츠를 계속 채워야 함**(유지보수 최소화 원칙 위반). 권장하지 않는다. |

## 5. 프로젝트 운영 규칙 (그대로 채택 권장)

1. **금칙어 목록을 코드에 둔다.** `Yahtzee, Yatzee, 야찌, Battleship, Monopoly, 부루마블, UNO, 우노, Scrabble, 스크래블, Jenga, 젠가, Catan, 카탄, Rummikub, 루미큐브, Othello, 오델로, Codenames, 코드네임, Connect 4, Mastermind, Wordle, 워들` — **빌드 시 정적 검사로 소스·문자열·메타태그·README를 grep해서 걸리면 빌드 실패**로 만든다. 유지보수 비용 거의 0이고, 사고의 90%가 "메뉴 라벨 한 줄"에서 나온다.
2. **"○○ 스타일" 비교 문구 금지.** 명목적 공정사용(nominative fair use)이 이론상 가능해도(Catan Board Generator가 그 논리를 쓴다), **다투는 비용이 우리 편이 아니다.**
3. **모든 아트는 자작.** 흰바탕/검은선 원칙이 이미 최상의 방어다 — 상용 게임의 trade dress는 대부분 **색**으로 성립하는데 우리는 색을 플레이어 구분에만 쓴다.
4. **점수판(scoreboard) 모드 주의.** 실물 게임 기록용 프리셋에 "루미큐브", "우노", "카탄" 같은 **게임명 프리셋을 넣지 않는다.** 사용자가 직접 이름을 입력하는 자유 입력 방식으로 두면 위험 0.
5. **한 줄 고지**: "이 사이트의 모든 게임은 퍼블릭 도메인 규칙의 독자 구현이며, 어떤 상표권자와도 제휴 관계가 없습니다."는 방어에 도움이 되지만 **면죄부가 아니다.** 이름을 안 쓰는 것이 먼저다.
6. **도메인·URL·PWA manifest name**까지 검사 대상. `/yahtzee` 경로 하나가 검색에 잡힌다.
