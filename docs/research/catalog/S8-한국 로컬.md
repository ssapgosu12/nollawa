# S8 — 한국 로컬 게임 조사

조사일: 2026-08-12 / 방법: 웹 검색(한국어 쿼리 10건) + 내부 지식
전제: 웹(PWA) · 흰 바탕 검은 선 + 플레이어 4색(노/빨/초/파) · 무서버(정적 호스팅 + 시그널링만) · 로컬 저장 · 유지보수 최소화 · 스마트폰 세로 화면 성립

---

## 0. 이 축의 결론 요약

- **가장 강한 후보는 "게임"이 아니라 "도구"다.** 사다리타기·랜덤 뽑기·다트/당구 점수판·마피아 진행판은
  전부 (a) 콘텐츠 유지보수 0, (b) 흰 바탕 검은 선 UI와 정면으로 맞고, (c) 서버가 아예 필요 없고,
  (d) 한국 사용자의 실제 반복 수요(회식 당번, 팀 나누기, 당구장, 다트바, MT)가 이미 검증돼 있다.
- **윷놀이가 이 축의 유일한 "대형 게임" 정답.** 저작권 프리, 4인=4색 팔레트와 정확히 일치,
  29점 보드라 세로 화면에 들어가고, 이미 P2P 방코드 방식 웹 구현체가 존재해 수요가 실증된다.
- **고스톱/맞고는 반드시 탈락.** 등급분류·사행성 규제 + 화투 48장 컬러 에셋(흑백 UI 정면 충돌) +
  지역 룰 방언으로 인한 무한 유지보수. 대신 **점수판만** 취하는 것이 안전한 회수 경로다.

## 1. 윷놀이 (Yut Nori)

### 수요 근거
- 넷마블 `윷놀이`, 한게임 `신윷놀이`가 대형 포털 게임으로 상시 서비스 중 — 장르 수요가 20년 넘게 유지됨.
  - https://game2.netmarble.net/yutgame/
  - https://game1.hangame.com/
- 구글플레이 `다같이 윷놀이`(com.devsquare.yuttogether): **"빠른시작 매칭과 방 코드 친구 초대", "게스트 로그인으로 회원가입 없이"**
  — 이 프로젝트의 방 코드 P2P 모델과 사용자 기대가 정확히 일치한다는 근거.
  - https://play.google.com/store/apps/details?id=com.devsquare.yuttogether
- 웹 구현체 `yutnori.olle.cc`는 **"실시간 P2P 멀티플레이어와 AI 봇 대전, 모바일 지원"**을 이미 표방.
  → 기술 스택(WebRTC + 봇)이 실현 가능함을 남이 증명해 준 사례. 동시에 경쟁자이기도 함.
  - https://yutnori.olle.cc/
- 실물 윷이 없을 때 쓰는 **"윷 던지기만" 하는 단품 도구**도 별도 수요로 존재.
  - https://xn--yq5bk9r.com/blog/random-yut
- 교사가 태블릿으로 쓰는 무료 윷놀이(sciencelove) — 교실/가족 수요.
  - https://sciencelove.com/2740

### 제약 적합성 실사
| 항목 | 판정 |
|---|---|
| 흰 바탕 검은 선 | ◎ 윷판은 원래 선과 점으로만 그린다. 말 = 4색 원. 색 정보 요구가 정확히 "플레이어 구분" 하나뿐 |
| 작은 세로 화면 | ◎ 노드 29개. 정사각 보드라 세로 화면 상단에 보드, 하단에 윷 던지기 버튼 배치로 성립 |
| 무서버 | ◎ 방 코드 P2P로 충분. 턴제라 지연 내성 큼 |
| 콘텐츠 유지보수 | ◎ 규칙 고정. 텍스트 자산 없음 |
| 저작권/상표 | ◎ 전통 놀이. 단 "신윷놀이" 같은 상용 타이틀명은 쓰지 않는다 |

### 구현 난도 요소 (3/5, 며칠)
- 윷 4개 던지기(도/개/걸/윷/모 + 백도) — 확률은 실제 윷의 비대칭 확률을 흉내낼지 균등으로 갈지 결정 필요.
- 말 **업기(합체)**, 잡기, 지름길(모/윷 자리 분기), 4말 완주 — 상태 머신이 생각보다 크다. 여기가 난도의 8할.
- 팀전(2:2)까지 넣으면 승패 판정이 한 겹 늘어남.

### 수요 근거

### 제약 적합성 실사
| 항목 | 판정 |
|---|---|
| 흰 바탕 검은 선 | ○ 9×10 격자 + 궁성 대각선. 기물은 한자 원형 문자. 초(楚)=파랑 / 한(漢)=빨강으로 2색만 사용 → 팔레트 내 |
| 작은 세로 화면 | ◎ 세로로 긴 보드(9열×10행)라 오히려 스마트폰 세로에 최적. 이 축에서 화면 적합도가 가장 좋은 게임 중 하나 |
| 무서버 | ◎ 턴제 P2P |
| 콘텐츠 유지보수 | ◎ 없음 |

### 구현 난도 요소 (4/5)
- 기물 7종 이동 규칙 + **포(包)는 넘을 말이 반드시 하나 필요하고 포끼리는 못 넘음** — 특수 케이스가 체스보다 지저분.
- **빅장(양 궁이 마주보면 무승부/승)**, 점수제 무승부(한 1.5점 덤), 초 선수 여부 등 룰 방언 존재 → 한 가지로 고정하고 문서화 필요.
- **AI는 목표 아님**(제약 명시). 대인전 + "무르기/기보" 정도로 끝내는 것이 정답.
- 체스 엔진 코드 구조를 그대로 재활용 가능(확정 코어에 체스가 있음) → 실제 비용은 4보다 낮아질 수 있다.

## 5. 랜덤 뽑기 / 제비뽑기 / 팀 나누기

사다리타기와 같은 수요 클러스터지만 **별도 화면으로 분리할 가치가 있다**(사다리는 "누가 걸리나", 뽑기는 "팀/순서 정하기").
- 위 randompick.co.kr / braindetox.kr 이 실제로 둘을 나란히 제공한다 = 시장이 이미 두 기능으로 인식.
- 필요한 것: 이름 입력 → (a) 1명 뽑기 (b) 순서 섞기 (c) N개 팀 분배 (d) 룰렛/핀볼 연출.
- 흰 바탕 검은 선 + 4색으로 팀 구분 → 팔레트가 **팀 나누기 최대 4팀**이라는 자연스러운 상한을 준다.
- 구현 1/5. 가장 싼 값에 실사용률이 붙는 항목.

## 6. 마피아 게임 진행판

### 수요 근거
- 나무위키 마피아 게임/규칙 문서가 유지될 만큼 오프라인 플레이 문화가 두껍다.
  - https://namu.wiki/w/마피아%20게임/규칙
- **핵심 페인포인트가 문서에 그대로 적혀 있음**: "오프라인에서 특수직업이 너무 많으면 진행이 원활하지 않고
  **특히 사회자에게 가는 부담이 커진다** → 사실상 경찰과 의사 정도만 등장시키는 게임이 대다수".
  → 즉 **디지털 진행판의 존재 이유 = 사회자 부담 제거**. 기능 목표가 명확하다.
- 엔트리(초중생 코딩 플랫폼)에 "[오프라인] 마피아 게임 : 사회자 없이 하는 게임" 프로젝트가 존재 = 아마추어까지 만들 만큼 수요가 있다.
  - https://playentry.org/project/607919ab6cab91006d33e95f
- 기존 앱들은 "최소 5인~최대 30인, 자동모드는 12인까지 비율 자동 배분" 수준의 UX를 제공 — 기능 벤치마크.

### 제약 적합성 실사
- 모드: **공용(shared)이 1순위** — 기기를 돌려가며 "당신은 마피아입니다"를 각자 확인(패스앤플레이 카드 뒤집기).
  멀티(P2P)는 각자 기기에서 자기 역할만 보는 상위 경험 → 방 코드로 구현 가능.
- 흰 바탕/4색: ◎ 역할은 아이콘+텍스트, 색 의존 없음.
- 화면: ◎ 리스트 UI.
- 유지보수: ◎ 역할 세트(마피아/시민/경찰/의사/스파이 정도)를 **고정하면 0**.
  단, "역할 20종 추가" 요구가 들어오면 콘텐츠 유지보수로 전락 → 처음부터 확장 안 한다고 못 박아야 함.
- 밤/낮 타이머 + 나레이션은 **텍스트 고정 문자열**이라 콘텐츠 축적이 아니다.

    https://www.thescoop.co.kr/news/articleView.html?idxno=309437
    https://www.gamevu.co.kr/news/articleView.html?idxno=55464 (월 결제한도 70→100만원, 2026-02-03 시행)
- **금액 환산 기능(점당 100원 등)은 넣지 않는 편이 안전하다.** 점수만 기록. 금액을 계산해 주면
  "도박 보조 도구"로 읽힐 여지가 생기고, 스토어 배포로 확장할 때(구글플레이 도박 정책) 곧바로 걸린다.

### 제약 적합성 실사 — 되지만 **매력이 약하다**
- 흰 바탕 검은 선: ○ 격자와 숫자. 단 원본은 숫자 1~8에 8색을 쓴다 → **4색 제약 하에서는 전부 검정 + 굵기/폰트로 구분**해야 함(가독성 실험 필요).
- 작은 화면: △ 초급 9×9는 OK, 중급 16×16부터 세로 화면에서 손가락 오조작. 확대/롱프레스 깃발 UX 필수.
- **본질 문제: 1인 게임이라 이 프로젝트의 3모드(공용/스플릿/멀티)에 안 맞는다.**

  그 순간 원조 지뢰찾기를 찾아온 사용자의 기대와 어긋난다.
- 경쟁 밀도 최상 + 차별화 수단 없음 → 우선순위 하위.

  - https://www.teacherville.co.kr/ssam/contents/view.edu?contentsSeq=14446

### ★약점 — 세 겹으로 걸린다
1. **한국어 사전이 필요하다.** 단어 유효성 판정 없이는 게임이 성립하지 않는다.
   국립국어원 우리말샘은 **CC BY-SA 4.0**이라 (a) 출처 표기 (b) **동일조건변경허락** 의무가 붙는다 → 라이선스 오염 검토 필요.
   표준국어대사전 API는 이용 신청·조건 확인이 필요. 사전 자체는 정적이라 "계속 채워 넣는" 부류는 아니지만,
   **번들 용량(수십만 표제어)과 "이 단어가 왜 안 되냐" 분쟁 대응**이 실질 유지보수로 돌아온다.
2. **화면.** 타일 랙 + 배치 보드는 정보 밀도가 높다. 스마트폰 세로에서 드래그 배치는 고통스럽다.
3. **선점.** 이미 4인 실시간 대전 앱이 나와 있어 차별점이 "무설치" 하나뿐.
→ 우선순위 하위. 하려면 보드 없이 "주어진 자모로 단어 만들기(제한 시간)" 미니게임으로 축소하는 편이 낫다.

## 13. ★탈락: 고스톱 / 맞고 본편

**넣으면 안 되는 이유 4가지.**
1. **등급분류.** 게임산업법상 "개인·동호회 등이 단순 공개를 목적으로 창작한 게임물"은 등급분류 면제지만,
   **청소년이용불가 기준에 해당하는 내용을 포함하는 게임물은 그 면제에서 제외**된다.
   화투/포커류 베팅 게임은 사행성 모사로 청불 판정 소지가 크다 → 개인 웹 공개라도 안전하지 않다.
   - https://easylaw.go.kr/CSP/CnpClsMain.laf?popMenu=ov&csmSeq=2858&ccfNo=1&cciNo=1&cnpClsNo=1
   - https://www.grac.or.kr/institution/etcform01.aspx
   - 자체등급분류사업자(구글/애플) 제도는 **청소년이용불가와 아케이드를 제외**하므로 스토어 우회도 막힘.
2. **스토어 정책.** 구글플레이는 시뮬레이션 도박 콘텐츠(소셜 카지노 등)를 원칙 금지, 허용은 국가별 승인 절차가 필요.
   iOS의 실제 고스톱 앱은 **19+ 등급**으로 유통된다(예: `고스톱 프리 프로` 19+).
   - https://support.google.com/googleplay/android-developer/answer/9877032?hl=ko
   - https://apps.apple.com/kr/app/고스톱-프리-프로/id1380004645
3. **UI 제약 정면 충돌.** 화투 48장은 **그림 카드**다. 흰 바탕 검은 선 + 4색 규칙에서 광/열끗/띠/피를 구분할 방법이 없다.
   기호화하면 화투를 아는 사람에게도 못 읽히는 물건이 된다.
4. **룰 방언 = 무한 유지보수.** 흔들기/폭탄/쓸/따닥/피박/광박/멍따/고박, 3점 시작 vs 7점 시작, 지역·집안 규칙.
   "우리 동네 룰이 없다"는 요청이 끝없이 들어온다.
→ **회수 경로는 9번(점수판)뿐.**

## 14. ★탈락: 초성 퀴즈 / 한국 상식 퀴즈류

- 수요는 확실하다(카톡 초성퀴즈, 유튜브 퀴즈 쇼트폼). 구현도 하루면 된다.
- 그러나 **재미의 100%가 문제 은행이다.** 제약 문서가 1순위로 배제한 "콘텐츠를 계속 채워 넣어야 하는 게임"의 원형.
  문제 300개를 넣으면 열성 사용자는 이틀이면 소진하고, 그 뒤로는 영원히 문제를 만드는 사람이 된다.
- 자동 생성(사전에서 랜덤 단어 → 초성)으로 유지보수를 0으로 만들 수는 있으나, 그러면 문제 품질이 무작위라
  ("ㄱㅅㅎ" → 감사합 같은 쓰레기 항목) 재미가 붕괴한다. 사전 큐레이션 = 결국 콘텐츠 노동.
- 결론: 이 프로젝트에 넣지 않는다. 기록용으로만 남긴다.
