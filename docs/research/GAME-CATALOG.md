# 게임 카탈로그 — 최종 수록 목록 (조사 통합 판정)

작성일: 2026-08-12. 조사 10개 축(추상전략 · 비대칭정보/추리 · 주사위 · 파티(한 기기) · 트럼프 카드 · 점수판 시장 · 경쟁 서비스 빈틈 · 한국 로컬 · 라이선스 위험 · 구현난이도)과 창의 변형 발상 1건을 통합했다. 축별 상세 근거·출처는 `docs/research/catalog/` 아래 각 문서에 있다.

## 요약 (3줄)

1. **최소 출시(T0)는 8종** — 오목·사목·육목·리버시·요트 다이스·범용 점수판·함대 격침·체스. 이 8종만으로 공용(한 기기)·멀티(방 코드)·점수판·스플릿 네 모드가 전부 실물로 성립한다.
2. **확정 코어 6종 중 바둑만 1차 확장(T1)으로 미룬다** — 계가·사석 판정 상태기계가 바둑 공수의 절반이라 최소 출시의 발목을 잡는다. 대신 규칙 한 줄짜리 변형 "원자바둑(먼저 따내면 승)"이 그 자리를 먼저, 하루 비용으로 메운다.
3. **법적 위험은 규칙이 아니라 이름과 그림에만 있다**(한국 법원 판례로 확인). 상표 리네임 목록을 지키고, "흰 바탕 + 검은 선 + 색은 플레이어 구분에만"이라는 UI 원칙을 지키면 상용 게임의 트레이드 드레스(겉모습) 위험층이 자동으로 제거된다.

## 포지셔닝 — 기존 서비스 대비 이 프로젝트의 존재 이유

1. **"무로그인 × 무광고 × 오프라인 PWA × 한 기기 로컬 플레이"의 결합은 시장에 없다.** 각 요소는 개별적으로 존재하지만(PlayOK 게스트=무로그인, 광고형 단품 사이트=로컬 2인, netgames=방 코드) 넷을 하나로 묶은 서비스가 없다. 세계 최대 체스 사이트 lichess조차 한 기기 대국을 웹에 두지 않았고 관련 요청 스레드만 쌓여 있다 — 기술 문제가 아니라 아무도 안 한 슬롯이다.
2. **폰 우선 설계가 실측으로 비어 있는 경쟁 축이다.** 가상 테이블 서비스(playingcards.io)가 자사 FAQ에서 "폰에서는 글자가 작아 읽기 어렵다"고 인정하고, Tabletopia 모바일은 이용자 평이 "사실상 플레이 불가"다. 작은 세로 화면에서 성립하는 게임만 고른 이 카탈로그 자체가 차별점이다.
3. **디지털 대전 + 실물 게임 점수판을 한 URL에 통합한 서비스가 없다.** 점수판 축에서는 이 프로젝트의 제약(무서버·무계정·무광고)이 결함이 아니라 그대로 셀링포인트가 된다 — 기존 점수판 앱의 리뷰 불만 상위(전면광고, 유료 재과금, 계정·동기화 오류)를 구조적으로 겪지 않는다.

## 판정 원칙 (티어 배분에 쓴 기준)

- **유지보수 0이 최상위**: 문제·카드·단어를 계속 채워야 하는 게임은 채택 불가(즉석 입력 이양 또는 유한 불변 집합만 예외).
- **한계비용으로 센다**: 게임을 독립 프로젝트로 세지 않는다. 보드 렌더러 3종(격자형·교점형·육각형)과 엔진(알파베타 AI 골격, 덱/손패, 커밋-리빌, 점수판 엔진)이 서면 후속 게임은 며칠→반나절로 떨어진다. 순서 원칙은 "싼 게임 먼저"가 아니라 **"싸면서 다음 것을 싸게 만드는 게임 먼저"**.
- **모드는 거짓 스펙 금지**: 스플릿(화면 분할)은 비대칭 정보와 원리적으로 양립 불가(옆에서 보인다) — 완전공개 게임과 개인 영역이 독립된 게임(요트 점수표)에만 붙인다. 은닉 정보 게임의 공용 모드는 반드시 "넘기기 전 가림" 화면을 전제한다.
- **P2P 신뢰 모델은 "아는 사람끼리"**: 방장 브라우저가 심판을 겸하므로 원리상 방장이 비밀을 볼 수 있다. 커밋-리빌(해시 지문 선교환)로 막을 수 있는 게임은 막고, 나머지는 지인 한정임을 명시한다. **랜덤 매칭 도입은 이 모델을 깨므로 영구 배제.**
- **수요는 실측만**: Board Game Arena 누적 판수, 앱 리뷰의 구체 불만, 한국어 서비스 실존 여부. GitHub 구현 수는 수요 지표가 아니다(강의 과제 공급일 수 있음 — 텐지 사례).

## T1 — 1차 확장 (10종)

> **진입 조건**: T0 출시 후 ① P2P 연결 성공률·재접속 복구가 실측으로 견딜 만함(무서버 P2P는 ~90% 성공률 서비스 — 실패 시 "공용 모드 전환" 폴백 확인) ② 렌더러 3종과 흑백 렌더링 결정이 안정 ③ 점수판 실사용 피드백 존재.

## 변형·고유 게임 제안 (창의 축 요약)

변형 발상의 핵심 교훈 4개가 티어 배치에 이미 반영돼 있다:

1. **최고 가성비 변형은 재미 추가가 아니라 비용 삭제** — 원자바둑이 규칙 한 줄로 바둑 공수의 절반(계가·사석·세키)을 삭제 → T1에서 바둑 본편보다 먼저.
2. **미제르(거꾸로 이기기) 계열이 스위트스팟** — 렌더러·AI 100% 재사용+승리조건 반전(역리버시·안티체스) → T3 변형 팩.
3. **기기 배치 축의 정답은 동시 비밀 커밋** — 블로토·구프스필·동시 영토가 커밋-리빌 재사용으로 2~3일 → T3 신작 묶음.
4. **점수판의 유일한 본질 부가가치는 은폐** — 비밀 임무 요트·블라인드 레이스·비밀 표적 다트 → T3 점수판 변형.
5. 스플릿 전용 신작은 발상 단계에서도 성립하지 않았다(비밀정보와 화면 공유 양립 불가) — 스플릿은 완전공개 게임(사목·도트앤박스)과 개인 영역 독립형(요트 점수표)의 부가 모드로만 존재한다.

## 점수판 설계 (최종 결론)

**범용 vs 전용 → "범용 엔진 1개 + 전용 프리셋". 판별 기준은 단 하나: 점수가 단순 가감산인가.**

- 범용 엔진(T0): 고점승/저점승·목표점/라운드수·표 입력/즉석 카운터·턴 타이머·라운드 이력·되돌리기. 카탄류 목표점 도달·타일 러미 감점·훌라·당구식 단순 기록 등 가감산 게임 전부를 프리셋 파라미터로 흡수.
- 전용 구현이 정당한 것(점수가 규칙 계산인 것)만 별도로: **요트(T0 내장) → 다트·당구(T1) → 고스톱 수동(T2) → 입찰 트릭·리치 마작(T3)**. 크리비지 페그보드는 한국 수요 부재로 탈락.
- **게임명 프리셋 금지**: "루미큐브·우노·카탄" 같은 상표를 프리셋 이름으로 넣지 않는다(자유 입력으로 두면 상표 위험이 0).

**공용 vs 개인 → 공용(탁상 위 기기 1대)이 기본.** 시장 증거가 일방적이다 — 개인 기기 분산 입력이 팔리는 곳은 골프·리그 운영뿐이고 존재 이유가 전부 상시 서버 리더보드(제약 위반). 반면 성공한 점수판 앱들의 셀링포인트(미러 레이아웃·점봉 교환 제거)는 전부 탁상 1기기 전제다. 개인 점수판은 독립 모드로 만들지 않고 정확히 두 형태로만 존재한다:

1. **통신 없는 로컬 개인 시트**(큐윅스형): 실물 주사위+각자 폰. 기기끼리 통신할 이유가 없으므로 P2P를 끌어들이지 않는다 — 그냥 로컬 저장.
2. **비공개 동시 입찰 P2P 옵션**(입찰 트릭 점수판 한정): 개인 화면이 서버 없이 정당화되는 유일한 사례이자 시장에 없는 물건. 단 옵션으로만 — 연결 없이도 공용 모드로 완결돼야 한다.

**구현 불변식**(기존 앱 실패 사례에서 도출): ① 점수는 입력 이벤트 목록→순수 함수 재계산으로만 유도(누적 변수 금지 — 열 합계 오염·반복 시 2배 누적 버그의 근원) ② 입력 1건마다 localStorage 즉시 커밋(웹은 탭 종료가 앱보다 흔함) ③ undo·라운드 이력 필수 ④ Screen Wake Lock(네이티브 앱은 안 겪어 벤치마킹으로 안 잡히는 웹 고유 함정) ⑤ 태블릿 거치용 대형 타이포+180° 미러 표시.

## 상표·법적 주의사항

**대원칙(한국 판례로 확인)**: 규칙과 진행 방식은 저작권 보호 대상이 아니다(서울중앙지법, 부루마블 vs 모두의마블 — 원고 패소). 겁낼 것은 **이름·그림·트레이드 드레스**뿐이고, 같은 판결이 칸 지명·랜드마크류는 보호된다고 했으므로 텍스트 콘텐츠는 전부 창작한다.

**필수 리네임 표** (게임 자체는 퍼블릭 도메인 — 개명으로 완전 해결):

| 상표(사용 금지) | 우리 표기 |
|------|------|
| Connect Four (해즈브로) | 사목 / 네 줄 잇기 |
| Othello (메가하우스) | 리버시 |
| Yahtzee·야찌 (해즈브로) | 요트 다이스 (점수표 항목명에도 금지) |
| Battleship (해즈브로) | 함대 격침 |
| Mastermind (인빅타/해즈브로) | 숫자야구 (숫자 형태로 색핀도 회피) |
| UNO (마텔) | 원카드 (표준 52장 — 4색 카드 디자인도 회피) |
| Quoridor (Gigamic) | 벽길 |
| Farkle | 만점 |
| Perudo (Asmodee 계열) | 라이어 다이스 / 거짓말쟁이 주사위 |
| Qwixx (NSV) · Rummikub · Catan · Skull King · Wizard | 자체 명칭·자유 입력 (점수판 프리셋에 게임명 금지) |
| 부루마블 (아이피플스) · 신윷놀이 등 상용 타이틀 | 사용 금지 |

**아예 손대지 않는 것**: Hive·Onitama·Santorini·Azul·Pente·Codenames·Hanabi·좀비 다이스·간지 셴 클레버 — 현역 상용 게임이거나 권리자의 팬 구현 삭제 이력이 있다. "보드게임 회사는 팬 구현을 봐준다"는 통념은 실집행 4건(Scrabulous·NYT/Wordle·Catan·Codenames)으로 반증됐다.

**정적 호스팅도 안전지대가 아니다**: GitHub Pages/Netlify는 신고로 내려가고, 상표 건은 DMCA 반박 절차조차 없어 개인에게 더 불리하다. 전략은 다투기가 아니라 회피 하나뿐.

**즉시 채택 2건**: ① **금칙어 빌드 게이트** — 위 상표 전부를 소스·문자열·메타태그·URL 경로·PWA manifest·README에서 grep, 걸리면 빌드 실패(사고 대부분이 메뉴 라벨 한 줄과 `/yahtzee` 경로에서 남). ② UI 원칙 자체가 방어막 — 상용 트레이드 드레스 대부분이 색으로 성립(UNO 4색, Connect4 빨강/노랑 원판, Wordle 초록/노랑 타일)하므로 흰바탕+검은선 원칙 준수가 곧 법적 회피다.

**도박성 가드**: 베팅·판돈·금액 환산 UI 전면 금지(고스톱 점수판·인디언 포커·훌라 포함 — 전부 점수 포인트로만). Apple은 개인 개발자의 시뮬레이션 도박 앱 제출을 금지하므로, 이 선을 넘는 순간 "APK는 최후 수단" 경로가 봉인된다.

## 미해결 질문 (착수 전 사용자 결정 필요)

1. **흑백 돌 렌더링 방식** — 흰 바탕에 흰 돌이 묻힌다. ①흰 돌+검은 외곽선 ②채움 vs 빗금 ③P1 노랑/P2 파랑 치환. 바둑·오목·육목·리버시·헥스·고누·체커 7종에 동시 적용되므로 **T0 착수 전에 한 번만** 결정해야 한다(늦게 바꾸면 7개 재작업). 권고: ①(실물 관습 보존)을 기본, ③을 접근성 옵션.
2. **트럼프 카드 팔레트 예외** — ♥♦ 빨강은 문화 고정인데 빨강은 플레이어 2번 색. ①슈트 색만 팔레트 예외 승인 ②전부 검정+기호 구분(작은 화면에서 ♥/♦ 실루엣 유사 위험). 솔리테어(빨검 교대가 규칙)가 가장 아프다. T2 카드 축 착수 전 결정.
3. **P2P 시그널링 방식** — "무료 정적 호스팅+최소 시그널링" 제약 내에서 무엇을 쓸지(무료 시그널링 서비스 vs 수동 코드 교환 등) 기술 조사·결정 필요. TURN 중계 없이 연결 성공률 ~90%임을 UI에 어떻게 알릴지 포함.
4. **스플릿 모드 검증 실패 시 처분** — 보드게임 스플릿은 시장 선례가 거의 없는 미검증 기회다. 사목·도트앤박스 실험에서 사용률이 없으면 모드 자체를 접을지(요트 점수표만 남김) 결정 기준을 미리 합의.
5. **워드울프 조건부 채택의 콘텐츠 하한** — "기본 소량+사용자 직접 추가"에서 기본이 몇 쌍이면 게임이 성립하는지(0쌍이면 첫 실행이 빈 화면). 이 하한이 콘텐츠 노동으로 번지면 탈락 전환.
6. **앱 전역 다전제 승패 카운터** — 실물 장기·바둑처럼 "몇 판 이겼나"만 세는 공용 카운터 1개를 게임별 기능이 아니라 전역 유틸로 둘지(추상전략 축 권고안) — 범용 점수판과의 경계 정의.
