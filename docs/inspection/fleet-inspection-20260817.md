## 2. 통과한 항목

### B-20 · 로컬 모드에서 2번째 플레이어가 진행 불가 — 통과

- **경로**: 이 기기에서 플레이 → 함대 격침 변형 → 3명이 시작.
- **1P(검수)**: 사격 카드 `piercing` 선택 → 특수 배 후보 4장(paper-ship · submarine · glass-cannon ·
  supply-ship) 중 paper-ship·submarine 선택 → 「프리셋 확정」이 노랑으로 활성 → 확정.
- **2P**: 화면이 「2P 프리셋」으로 바뀌고 카드가 buckshot · tracer · flare로 새로 뽑혔다.

  **네 버튼 모두 선택 표시가 없었으며 「프리셋 확정」은 `disabled=true`로 시작**했다.
  1P가 고른 배가 남아 있지 않다 — 이것이 결함의 핵심 증상이었다.

### B-42. 세로 폰 폭에서 배 목록이 좌우로 잘려 첫 배와 마지막 배를 선택할 수 없다 — **블로커**

  **첫 배 base-2는 x=-50(왼쪽 화면 밖), 마지막 배 submarine-4는 x=486~549(오른쪽 화면 밖)** 에 놓인다.

- **왜 지금까지 안 보였나**: 게임 틀 폭은 화면 높이에 비례한다(9:16). 2026-08-15 검수의 틀은 668px이라

- **얽힌 항목**: 배 이름이 영문 내부 ID(`base-3-a`·`submarine-4`)라 버튼이 넓다(B-14, 미착수).

- **사양 절**: §4.7 중단 = 배 선택과 회전(D-043·D-044) · D-045(세로 화면 기준) ·

### B-43. 프리셋 화면의 사격 카드가 상단 좌측 15% 칸에 들어가 글자가 세로로 찌그러진다

- **관측**: 프리셋 화면 상단에서 사격 카드 세 장이 **좌측 15% 칸(폭 68px)** 에 들어가 있고
  **중앙 70% 칸(폭 318px)은 빈 `.fleet-side setup-side`** 가 차지한다.
  그래서 「salvo · 특수 배 4종」이 한 글자씩 세로로 흐르고, 화면 오른쪽 3분의 2가 통째로 비어 있다.
- **좌표 실측**: `.fleet-upper`의 열이 68 / 318 / 68로 정확히 15/70/15인데,
  DOM 순서상 중앙 칸에 빈 side가, 좌측 칸에 `.fleet-board.fleet-summary`(카드 목록)가 들어간다.
- **사양 절**: D-045 「용도를 적지 않은 칸은 공란」 — 상단 좌·우가 공란이고 내용은 중앙에 와야 한다.

### B-1 · 배 후미 텍스처가 좌우 반전돼 형상이 끊긴다 — 통과

- **가로 배**: 하단 보드를 3배로 확대해 관측했다. 배의 **바깥쪽 끝(후미)이 각진 반 정사각형으로 닫히고**
  몸통을 지나 선두의 둥근 반원까지 하나의 윤곽으로 이어진다.
  종전처럼 바깥 끝이 열려 있거나 배 중간에 닫힌 세로선이 생기지 않는다.
- **세로 배**: 3칸 배를 (3,3)에 놓고 「회전」을 눌러 (3,3)·(4,3)·(5,3) 세로로 만든 뒤 2.6배로 확대했다.
  **위쪽 끝이 각진 후미, 아래쪽 끝이 둥근 선두**로 같은 방향 규칙이 90도 돌아간 채 유지되고 윤곽이 끊기지 않는다.
  §4.8의 [도출] 「세로로 놓인 배는 같은 텍스처를 90도 돌려 쓴다」대로다.
- **관측 방법 메모**: `computer`의 `zoom`은 뷰포트를 망가뜨리므로 쓰지 않았다.
  대신 보드 요소에 `transform: scale()`을 임시로 걸고 관측 뒤 원복했다.
- **회전 동작 확인**: 「회전」은 **이미 배치된 배**를 그 자리에서 돌린다(`fleet.ts:235` — origin이 `cells[0]`).
  배치 전에 누르면 아무 일도 일어나지 않는다. 기준점이 선미인 것은 **B-23(미착수)** 몫이다.

### B-2 · 예광탄이 판 가장자리를 쏘지 못함 — 통과

- **판**: 로컬 3인 변형(12×12). 1P가 사격 카드 `tracer`를 뽑을 때까지 판을 7번 새로 돌려 조건을 만들었다.
- **모서리 (1,1) 사격**: 사격이 성립했고 예약된 칸은 **(1,1)·(1,2)·(2,1) 세 칸**이다.
  판 밖으로 나가는 위·왼쪽 두 칸만 버려졌고, 종전처럼 사격 전체가 무효가 되지 않는다.
- **라운드 판정 뒤 화면**: 2P 보드 좌상단에 표기 세 개가 찍혔다(스크린샷).
  세 칸이 모두 빨강 ×인 것은 조명탄 표기가 아직 명중과 합쳐져 있기 때문이며 **B-4(미착수)** 몫이다.
- **발수**: 예광탄은 §3에서 「매 턴 예광탄 1발」이므로, 첫 발 뒤에 두 번째·세 번째 칸을 눌러도 예약되지 않는 것은
  사양대로다. 다만 눌렀을 때 아무 안내가 없는 것은 **B-7(미착수)** 몫이다.

### B-3 · 유리대포의 압박 고폭탄이 언제나 조명탄 1발 — 통과 (다만 B-44)

- **판**: 로컬 3인 변형. 2P가 특수 배 `glass-cannon`을 골라 함대에 `glass-cannon-1`(1칸)이 들어갔다.
  그 상대인 1P·3P의 중단에 **「압박 고폭탄」 버튼**이 1라운드부터 나타났다.
- **1P가 기본 사격 1발을 확정한 뒤** 압박 고폭탄으로 (6,6)을 지정하니
  **(5,6)·(6,5)·(6,6)·(6,7)·(7,6) 십자 5칸**이 예약됐다. 조명탄 1발로 바뀌지 않는다.
- 라운드 판정 뒤 2P 보드에 기본 사격 1칸 + 십자 5칸이 그대로 찍혔다(스크린샷).
- **조건**: 기본 사격을 먼저 확정하지 않으면 압박 고폭탄이 조용히 무효가 된다 — **B-44**로 따로 발행한다.
- 구현 위치 확인 — `fleet.ts:315`의 제공 조건이 `roundIndex % 2 === 0`(1·3·5라운드)이고
  `FleetGame.tsx:221`의 버튼 표시 조건이 `(state.round ?? 1) % 2 === 1`로 서로 맞는다.
  종전에 「제공되는 라운드가 곧 조명탄으로 바뀌는 라운드」였던 어긋남이 사라졌다.

### B-44. 압박 고폭탄을 기본 사격보다 먼저 고르면 조용히 무효가 된다

- **관측(2회 재현)**: 1라운드 시작 직후 「압박 고폭탄」을 누르고 표적 칸 (6,6)을 찍은 뒤 「확인」을 누르면,
  **선택이 사라지고 아무 사격도 예약되지 않는다.** 「모든 발 회수」와 「사격 확정」이 계속 비활성이라

## 5. 검수 방법 메모 (2026-08-15 4절의 증보)

지난 문서의 다섯 항목은 그대로 유효하다. 이번에 추가로 확인한 것만 적는다.

1. **크롬 창을 폰 크기로 줄이는 것은 `resize_window`로 되지 않는다.** 창이 최대화 상태이면
   도구가 성공을 반환해도 뷰포트가 그대로다. PowerShell의 `MoveWindow`로 창 자체를 옮겨야 하고,
   **비활성(백그라운드) 탭은 창 크기 변경이 반영되지 않는다** — 그 탭을 앞으로 가져와야 뷰포트가 바뀐다.
   크롬의 최소 창 폭 제약으로 뷰포트는 약 500px 아래로 내려가지 않는다.
2. **`computer`의 `zoom` 대신 `transform: scale()`을 쓴다.** 배 텍스처처럼 확대가 필요하면
   대상 요소에 임시로 `transform`을 걸고 관측한 뒤 원복한다. `zoom`은 뷰포트를 복구 불가능하게 망가뜨린다.
3. **클릭 직후 첫 `screenshot`이 CDP 타임아웃으로 실패하는 일이 잦다.** 한 번 더 호출하면 성공한다.
4. **배치를 스크립트로 자동화할 때는 단계마다 300ms 이상 기다린다.** 120ms로는 배 선택이
   이전 배치의 리렌더 전에 들어가 엉뚱한 자리에 놓인다 — 앱 결함이 아니라 조작 타이밍 문제다.
5. **사격 카드는 무작위 3장이라 특정 탄종을 보려면 판을 여러 번 새로 돌려야 한다.**
   이번에 `tracer`를 얻는 데 7판이 걸렸다. 좌석마다 카드가 따로 뽑히므로 1P 카드만 보고 재시작하면 빠르다.
6. **서비스워커 검수는 다른 탭의 판을 흔든다.** origin 단위로 공유되므로 한 탭에서 갱신하면
   같은 브라우저의 다른 탭에도 배너가 전파된다. 검수를 나눠 맡길 때는 이것을 교차 증거로 쓸 수 있다.
